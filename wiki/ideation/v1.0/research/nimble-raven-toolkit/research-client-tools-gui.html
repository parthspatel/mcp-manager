Research — Rust GUI tooling for the MCP Manager GUI

The MCP Manager GUI is closest in spirit to Docker Desktop: a single application that exposes server lists, config editors, logs, and resource graphs in a familiar window-and-sidebar layout. The Rust GUI space has two broad families — WebView hybrids and pure-native renderers — and neither is dominant. The boringcactus 2025 survey of 43 libraries concluded that no single "obvious" choice has emerged .

WebView-hybrid frameworks

These embed the OS's native WebView (Edge WebView2 on Windows, WKWebView on macOS, WebKitGTK on Linux) and let you write UI in whatever web stack you like — TS/React, Rust/WASM (Leptos, Dioxus, Yew), or vanilla HTML.

Tauri 2

Tauri 2.0 reached stable on October 2, 2024, adding first-class mobile (iOS & Android) targets, an ACL-based permissions/scopes/capabilities security model, and a new IPC implementation that uses custom protocols rather than serializing every message through the webview's postMessage interface . The new tauri::ipc::Channel API lets Rust stream data (file chunks, log lines) to the frontend with much lower overhead than the v1 IPC .

Tauri uses tao for window management and WRY for the WebView abstraction, and ships under MIT or Apache 2.0 . Real-world Tauri apps are typically ~600 KB – 10 MB installers versus 80–150 MB for an equivalent Electron app, with idle RAM in the 30–50 MB range vs. larger Electron footprints .

Frontend choice is open: create-tauri-app ships templates for React, Vue, Svelte, Solid, Angular, Yew, Leptos, Dioxus, and vanilla; the Leptos integration guide is a first-party doc . This means a Tauri app for MCP Manager can be 100% Rust (Rust backend + Rust-WASM Leptos/Dioxus frontend), or it can let the team start with a TS frontend they already know. 

// Tauri 2: a typed command using the new Channel API to stream events.
use tauri::ipc::Channel;
use serde::Serialize;

#[derive(Clone, Serialize)]
#[serde(rename_all = "camelCase", tag = "event", content = "data")]
enum LogEvent<'a> {
    Line { stream: &'a str, text: &'a str },
    Closed,
}

#[tauri::command]
async fn tail_logs(server: String, on_event: Channel<LogEvent<'_>>) {
    // ... read from the MCP Manager daemon and stream lines ...
    on_event.send(LogEvent::Line { stream: "stdout", text: "hello" }).ok();
    on_event.send(LogEvent::Closed).ok();
}

Dioxus 0.6 — desktop target

Dioxus targets web, desktop, mobile, and SSR with a single component model that visually resembles React; the desktop target runs on the same system WebView as Tauri . The 0.6 release in late 2024 brought magical hot-reloading of formatted strings and properties, an interactive CLI rewrite, inline WASM stack traces, and "Server Functions for Native" — inline RPC for desktop/mobile apps . 

// Dioxus desktop — components live entirely in Rust.
use dioxus::prelude::*;

fn main() { dioxus::LaunchBuilder::desktop().launch(App); }

fn App() -> Element {
    let mut count = use_signal(|| 0u32);
    rsx! {
        h1 { "Servers" }
        button { onclick: move |_| count += 1, "Refresh ({count})" }
    }
}

Compared to Tauri, Dioxus desktop avoids the JS<->Rust IPC boundary entirely — event handlers are normal Rust functions — but it locks the UI into the Dioxus component model, while Tauri lets you bring any frontend stack .

Pure-native frameworks

These render their own UI on the GPU (wgpu / Metal / DirectX / Skia) or a software canvas, and do not use a system WebView.

egui + eframe

egui is an immediate-mode GUI library inspired by Dear ImGui: the UI is reconstructed each frame, with no retained widget tree . It compiles to native Windows/macOS/Linux/Android and to WebAssembly, has no unsafe code, minimal dependencies, and an official framework wrapper called eframe that handles input and rendering . Accessibility comes from AccessKit, with platform integrations on Windows and macOS enabled by default in eframe .

The largest production user is Rerun, which sponsors egui development and ships a multimodal data visualization viewer built entirely on it . egui's own README is candid that "if you want a GUI that looks native or something that doesn't break when you upgrade it, egui isn't for you (yet)" . 

// egui — immediate-mode app via eframe.
use eframe::{egui, App, Frame};

struct McpApp { servers: Vec<String> }

impl App for McpApp {
    fn update(&mut self, ctx: &egui::Context, _: &mut Frame) {
        egui::CentralPanel::default().show(ctx, |ui| {
            for s in &self.servers { ui.label(s); }
            if ui.button("Refresh").clicked() { /* ... */ }
        });
    }
}

iced

iced is Elm-inspired and built around four concepts: state, messages, view, and update . It has two renderers — a primary wgpu renderer (Vulkan/Metal/DirectX 12) and a tiny-skia software fallback — plus first-class async/futures integration . Version 0.14, released December 2025, added reactive rendering (only redraws changed widgets), the Comet time-travel debugger, and a public Animation API as the final experimental release before 1.0 .

The flagship production user is System76's COSMIC desktop, which launched as Pop!_OS 24.04 LTS in December 2025 — a full Wayland desktop environment built on iced . iced is MIT-licensed and has 30k+ GitHub stars . 

// iced — Elm-style Application.
use iced::{Element, Task};

#[derive(Default)] struct State { count: u32 }
#[derive(Clone, Copy)] enum Msg { Inc }

fn update(s: &mut State, msg: Msg) -> Task<Msg> {
    match msg { Msg::Inc => s.count += 1 } Task::none()
}

fn view(s: &State) -> Element<'_, Msg> {
    iced::widget::button(iced::widget::text(format!("{}", s.count)))
        .on_press(Msg::Inc).into()
}

Slint

Slint defines UI in .slint — a declarative DSL akin to HTML/CSS — and compiles it into native code, with bindings for Rust, C++, JavaScript, and Python . The runtime fits in less than 300 KiB of RAM and runs on systems as small as a Raspberry Pi Pico . AccessKit is integrated .

Slint reached 1.0 in 2023 and explicitly commits to API stability going forward . It is dual-licensed: GPLv3 for open-source apps, with a separately purchased royalty-free permissive license for proprietary use . The boringcactus 2025 survey rates it as one of the few frameworks with strong accessibility plus IME plus production-ready widgets . 

// Slint — UI in a .slint file, logic in Rust.
slint::slint! {
    export component MainWindow inherits Window {
        VerticalBox {
            Text { text: "MCP Manager"; }
            Button { text: "Refresh"; clicked => { root.refresh-now(); } }
        }
        callback refresh-now();
    }
}

fn main() {
    let w = MainWindow::new().unwrap();
    w.on_refresh_now(|| println!("clicked"));
    w.run().unwrap();
}

GPUI

GPUI is the framework that powers the Zed editor — a hybrid immediate/retained mode, GPU-accelerated UI framework that uses Metal on macOS . The official site states GPUI "is still in active development as we work on the Zed code editor, and is still pre-1.0. There will often be breaking changes between versions" .

Platform support is currently macOS and Linux; Windows support is being actively built but is not at parity . The crates.io listing reinforces the pre-1.0 caveat . The boringcactus survey flags that GPUI "lacks basic text input widget; overly complex to use" for general-purpose apps as of 2025 .

Freya, Xilem, Makepad — earlier-stage

  • Freya uses the Dioxus core but renders natively with Skia — RSX components on a non-WebView backend . The boringcactus survey rates it as "basically usable now if you don't mind living on the bleeding edge and putting up with some jank" .
  • Xilem is a Linebender project — a reactive framework inspired by React, SwiftUI, and Elm, built on Masonry. It hasn't had a numbered release in nearly a year as of the 2025 survey and is alpha-quality .
  • Makepad hit 1.0 in 2025 but the survey notes it appears built primarily for its own team, with a macro DSL that has minimal documentation; crates.io versions don't get matching Git tags .

Accessibility status

Accessibility ("can a screen reader use this app?") is the single most differentiating axis among Rust GUI frameworks. AccessKit is the cross-toolkit infrastructure layer that surfaces a UI tree to platform accessibility APIs (UIA on Windows, NSAccessibility on macOS) . It's integrated by Bevy, egui, Freya, Slint, and Xilem.

The headline reality from the boringcactus 2025 survey is that of the 43 libraries the author tested, 94% failed his minimal "label + input field with proper screen reader and IME support" test . The four that passed were Slint, egui, Dioxus, and WinSafe (the last being Windows-only). That is the empirical pool the MCP Manager GUI choice should draw from, plus Tauri (which inherits the WebView's behavior, just like Dioxus) and iced (acceptable if a11y is not a P0).
