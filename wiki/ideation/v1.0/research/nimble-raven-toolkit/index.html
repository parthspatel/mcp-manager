Stream 5 · nimble-raven-toolkit — Client tooling selection

This stream surveys the Rust ecosystem for each of the MCP Manager's three client surfaces — CLI, TUI, and GUI — and recommends a stack for each. It deliberately treats the cross-client API as a black box (that's Stream 4) and focuses on what each framework provides for rendering, input, ergonomics, accessibility, and cross-platform reach. The result is a stack-per-surface plus a shared mcp-client crate that absorbs the parts that don't belong inside any specific UI layer.

Stream summary in one paragraph

For the CLI, the Rust ecosystem has consolidated around clap with the derive feature; alternatives like bpaf, argh, and pico-args only make sense under specific compile-time or binary-size constraints we don't have . For the TUI, ratatui on the crossterm backend is effectively the standard — production proofs include bottom, gitui, and yazi . For the GUI, the ecosystem is still moving: Tauri 2 with a Rust-WASM frontend (Leptos/Dioxus) and egui via eframe are the two most defensible production stacks today; Slint is the strongest pure-native option but encumbered by a GPL-or-paid license model . The volatility lives almost entirely in the GUI layer, which is why the recommendation page treats Tauri as the near-default and pure-native (egui/Slint/iced) as flippable on evidence.
