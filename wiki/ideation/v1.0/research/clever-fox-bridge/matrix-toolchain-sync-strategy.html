Ranking matrix — toolchain sync strategy

Seven sync strategies (push, managed-block, pull-only, three-way merge, overlay, watch+reconcile, symlink) scored against nine criteria (idempotency, hand-edit preservation, conflict safety, security blast-radius, cross-platform portability, implementation complexity, debuggability, escape-hatch friendliness, UX clarity). Weights default to a hand-edit-preservation-leaning configuration explained below; drag the sliders to test sensitivity.

Default weighting rationale

The default weights privilege hand-edit preservation (0.16) above all others because Stream 1's research established that users routinely hand-edit MCP config; a strategy that destroys those edits fails on first contact with reality. Idempotency, conflict safety, and security blast-radius are tied at 0.13 because they are co-dependent — idempotency without conflict safety still loses edits, and conflict safety without low blast-radius still endangers users. Cross-platform portability (0.10) and implementation complexity (0.10) follow because a strategy that only works on macOS or that takes six months to ship is not a strategy v1.0 can adopt. Debuggability (0.09) and escape-hatch friendliness (0.09) reflect the long-tail-tool concern that motivated this stream's existence in the first place. UX clarity (0.07) is the residual: when in doubt, prefer the design the user can explain to a colleague.

Note that blast and complexity are inverted dimensions — lower raw values are better — but they are stored as 0–5 scores where 5 means "low blast / low complexity", so the standard weighted-sum still works. The direction field in the data documents this for any future analyst tempted to reinterpret.

How to read the result

With the default weights, managed-block wins by a margin that does not collapse under any single-criterion reweighting short of zeroing out hand-edit preservation. Three-way merge is a close second when implementation-complexity weight is dialed down; its strength is conflict honesty but its weakness is debugging the merge-conflict UX on structured formats.

Push (overwrite) only wins when the user effectively zeros out hand-edit preservation and conflict safety — i.e. accepts that MCP Manager owns the file. Pull-only dominates when blast-radius is weighted very high and UX inconvenience is acceptable. Watch+reconcile is always last under our defaults because it amplifies the blast radius, which we weighted heavily.

The interesting sensitivity: overlay/kustomize-style rises to competitive when escape-hatch friendliness and idempotency are jointly weighted up. That suggests it could be a future v2 default if we ever decide community-supplied toolchain manifests are the dominant case — but in v1.0 the implementation cost (two-file model in every target, where most target tools don't natively read overlays) keeps it second-tier.
