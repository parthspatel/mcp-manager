Catalog of known MCP-consuming clients

For each tool MCP Manager could project into, this page documents: the exact file path(s) per OS, the schema shape, the env-var expansion syntax, whether the tool understands stdio / HTTP / SSE transports, the per-project vs global precedence model, the MCP-spec version supported, and any known deprecations or migration footguns. Stream 1 (curious-otter-survey/research-mcp-config-schema.html) already enumerated the on-disk JSON shapes; this catalog focuses on the projection-relevant facts our writer needs.

Tier-1 candidates

Claude Code CLI — ~/.claude/settings.json + .mcp.json
Paths User: ~/.claude/settings.json
Project: <repo>/.claude/settings.json and <repo>/.mcp.json
Enterprise: /Library/Application Support/ClaudeCode/managed-settings.json on macOS, /etc/claude-code/managed-settings.json on Linux
FormatJSON. Top-level key mcpServers (object).
Transport discriminatorOptional type field (stdio / http / sse, alias streamable-http). Without it, presence of command vs url determines transport.
Env expansion${VAR} and ${VAR:-default}. Resolved by Claude Code at server-start time, not config-load time.
Secrets patternInline env map values or headersHelper (executable that prints JSON of HTTP headers per invocation).
Scope precedenceEnterprise > CLI flags > project local > project shared > user. Project .mcp.json requires explicit approval on first load.
MCP spec versionTracks current spec; supports Streamable HTTP and stdio.
Projection notesStrict JSON — comments are not allowed, so managed-block markers must use sentinel keys ("_mcpManagerManaged") rather than comment fences. Prefer projecting into a sibling file (.mcp.json) so the user's settings.json is never touched.
Codex CLI (OpenAI) — ~/.codex/config.toml
Paths~/.codex/config.toml on Unix; %USERPROFILE%\.codex\config.toml on Windows.
FormatTOML. MCP servers declared as [mcp_servers.name] tables.
Transport discriminatorImplicit: only stdio supported as of 2026-Q1; command + args + env table.
Env expansionNone — TOML strings are literal; user must inline or use shell wrappers.
Secrets patternInline only as of this writing; this is one of the strongest arguments for our secret-reference rewriter.
Scope precedenceSingle user-scope file. No project-local override.
Projection notesTOML supports comments, so a fenced managed block is straightforward. The whole [mcp_servers.*] region is a natural fence boundary.
VS Code (native MCP, GA April 2025) — .vscode/mcp.json and user settings.json
Paths Workspace: <repo>/.vscode/mcp.json
User (macOS): ~/Library/Application Support/Code/User/settings.json
User (Linux): $XDG_CONFIG_HOME/Code/User/settings.json
User (Windows): %APPDATA%\Code\User\settings.json
FormatJSON-with-comments (JSONC). Top-level key in workspace file is servers (NOT mcpServers) and lives under mcp.servers in user settings.
Transport discriminatorExplicit type field: stdio or http.
Env expansion${env:VAR} for environment, ${workspaceFolder} for paths, ${input:id} for prompted secrets.
Secrets patterninputs array at top level — declares prompt-on-first-use values that VS Code caches in its secret storage. Best-in-class for security.
Scope precedenceWorkspace overrides user.
Projection notesJSONC tolerates // comments as managed-block fences. Top-level key disagreement (servers vs mcpServers) is the most common porting footgun — the projector must rewrite the key, not just the body.
Cursor — ~/.cursor/mcp.json and .cursor/mcp.json
PathsUser: ~/.cursor/mcp.json. Project: <repo>/.cursor/mcp.json.
FormatJSON. Top-level key mcpServers.
Transport discriminatorOptional type field (stdio default).
Env expansion${env:VAR}. Also supports envFile pointing at a .env file.
Scope precedenceProject overrides user.
Projection notesPure JSON. Same comment-restriction as Claude Code; use sentinel-key fencing or full-file ownership.
Zed — ~/.config/zed/settings.json
Paths macOS/Linux: ~/.config/zed/settings.json
Windows: %APPDATA%\Zed\settings.json
FormatJSON-with-comments. Top-level key context_servers.
Transport discriminatorPresence of command vs url; explicit source: "custom" distinguishes user-defined servers from extension-provided ones.
Env expansionNot documented; values are literal. The user is expected to provide already-resolved env in the JSON map.
Scope precedenceProject .zed/settings.json can override user, but Zed canonically scopes MCP at the user level.
Projection notesJSONC tolerates comments — managed-block fences work. Key name (context_servers) and the source: "custom" tag are both projection-time concerns.
JetBrains family (IntelliJ, PyCharm, RustRover, WebStorm, CLion, GoLand) — per-IDE options/mcp.xml
Paths Each IDE writes to a versioned config directory: ~/Library/Application Support/JetBrains/<Product><Year.x>/options/mcp.xml on macOS; ~/.config/JetBrains/<Product><Year.x>/options/mcp.xml on Linux; %APPDATA%\JetBrains\<Product><Year.x>\options\mcp.xml on Windows. The 2025.2 release added MCP support across the platform.
FormatXML — IntelliJ Platform component-state format. NOT JSON.
Transport discriminatorXML attribute type on each server element.
Env expansionIDE-internal macro syntax ($USER_HOME$, $PROJECT_DIR$); env vars only via explicit <env> children.
Secrets patternIDE keychain integration via UI; XML stores references not literals.
Scope precedenceIDE-wide; no per-project MCP file. Per-project overrides happen via .idea/mcp.xml on some 2025.3+ EAP builds but are not stable.
Projection notesXML format means we cannot share the JSON-projection code path. The projector needs an XML writer with managed-element fencing (<!-- BEGIN MCP-MANAGER --> XML comments). Toolbox-installed IDEs use distinct directories per major.minor version; the discovery step (see research-toolchain-discovery) must enumerate all installed JetBrains products.

Tier-2 candidates

Windsurf — ~/.codeium/windsurf/mcp_config.json
Paths macOS/Linux: ~/.codeium/windsurf/mcp_config.json
Windows: %USERPROFILE%\.codeium\windsurf\mcp_config.json
FormatJSON. mcpServers key.
Transport discriminatorPresence of command vs serverUrl/url.
Env expansion${file:/path/to/file} for file contents; not full env expansion.
Projection notesPure JSON; same caveats as Claude Code / Cursor.
Continue.dev — ~/.continue/config.yaml
Paths~/.continue/config.yaml (user); <repo>/.continue/config.yaml (workspace).
FormatYAML. mcpServers is an array (not an object). Each entry requires a name field.
Transport discriminatorExplicit type: stdio / sse / streamable-http.
Env expansion${{ secrets.X }} Mustache-style syntax for secrets; not generic env.
Projection notesArray vs object is the key projection difference — canonical state must be re-shaped at write time. YAML comments support managed-block fences cleanly.
Cline — cline_mcp_settings.json (VS Code extension storage)
Paths~/Library/Application Support/Code/User/globalStorage/saoudrizwan.claude-dev/settings/cline_mcp_settings.json on macOS; analogous globalStorage paths on Linux/Windows.
FormatJSON. mcpServers object.
Transport discriminatorPresence of command vs url; disabled boolean, autoApprove array of tool names.
Projection notesPath lives inside VS Code's extension globalStorage — coupled to the extension publisher ID; we must detect the extension installation before projecting.
Goose (Block) — ~/.config/goose/config.yaml
Paths~/.config/goose/config.yaml (Linux/macOS).
FormatYAML. Top-level key extensions (map).
Transport discriminatortype: stdio | sse | builtin. builtin is in-process and has no equivalent we can project.
Secrets patternOS keyring by default; GOOSE_DISABLE_KEYRING falls back to env. Secret references live in the env map.
Projection notesTop-level key disagreement (extensions vs mcpServers) is the projection-time rewrite.
LibreChat — librechat.yaml
PathsApp-root librechat.yaml; deployment-specific.
FormatYAML. mcpServers map.
Transport discriminatortype: stdio | sse; additional iconPath, timeout.
Projection notesThis is a hosted/multi-tenant deployment artifact; projecting requires being on the same machine as the deployment.
Claude Desktop — claude_desktop_config.json
Paths macOS: ~/Library/Application Support/Claude/claude_desktop_config.json
Windows: %APPDATA%\Claude\claude_desktop_config.json (or virtualized MSIX path)
FormatJSON. mcpServers object.
Projection notesTier-2 only because (a) it duplicates Claude Code coverage for most users and (b) MSIX virtualization on Windows is a footgun: the file the app reads differs from the file the user sees.

Out of scope for v1.0

  • Open WebUI — uses MCPO (a stdio-to-OpenAPI proxy) rather than native MCP. Projecting into MCPO would require us to model OpenAPI tool definitions, not MCP servers.
  • JetBrains Fleet — separate from the IntelliJ Platform; its MCP support is in early access and config tree is unstable.
  • Generic LangChain / LlamaIndex apps — these consume MCP programmatically with no canonical config file to project into.
  • MCP Inspector — debugging tool, not a long-lived agent host; users invoke ad-hoc.
