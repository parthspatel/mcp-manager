Closing gap · Secrets lifecycle

Every MCP server worth running needs a token: a GitHub PAT, a Linear API key, an Anthropic key, a database URL. Today those tokens get pasted into editor config files in plaintext — OWASP MCP01:2025 calls this the most common MCP failure mode. This stream designs the minimal v1.0 secrets surface (CLI write to OS keychain, daemon read-and-inject at spawn, audit-logged) and — more importantly — the Rust trait that lets v1.1+ plug in 1Password, Vault, Doppler, Infisical, AWS/GCP/Azure secret managers without re-architecting anything. 32 citations 2 v1.0 stores 6 v1.1+ stub stores sketched

One-paragraph summary

v1.0 ships a single hard-coded SecretStore impl: OsKeyringStore, backed by macOS Keychain Services and Linux Secret Service (via libsecret) through the keyring-rs crate. A second built-in impl, EnvVarPassthroughStore, is a read-only escape hatch: if the user has already exported GITHUB_TOKEN in their shell, mcpd uses that without touching the keychain. The two are composed into a LayeredSecretStore that the daemon consults at server-spawn time. The SecretStore trait is the v1.1+ extension point — later we plug in OnePasswordStore (shells out to op read), VaultStore (HTTP API), DopplerStore, InfisicalStore, and the three cloud vault stores, all behind the same trait. Every read and write emits a structured secret.read or secret.write audit event through mcp-core's audit channel; values never appear. The CLI accepts secrets only via interactive prompt (rpassword, hidden input, reads from /dev/tty) or --from-file / --from-env — never via --value, which would land in shell history .

What's locked in (do not relitigate)

  • macOS + Linux only; no Windows ever.
  • OS keychain only in v1.0 — no file-based fallback. If the platform secret service is unreachable, fail loudly.
  • Pre-existing env-var secrets are honored without re-storing (escape hatch for users who manage their own).
  • Secret values are injected as env vars into MCP server child processes by mcpd. The mcpm exec wrapper never sees plaintext.
  • Audit events: secret.read, secret.write, secret.unset. Names + actors, never values.
  • No GUI. CLI prompt is terminal-based (getpass-style).
  • Apache 2.0 throughout; copyleft-only vault providers (none of the listed ones qualify) would be flagged here.
