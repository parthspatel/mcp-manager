Research — Tauri 2 + Leptos as a desktop stack in 2026

This page is the framework-level research: what Tauri 2 and Leptos actually are in mid-2026, how they fit together, what the build pipeline looks like, where the rough edges are, and who is shipping this combination in production. Tauri 2 — the desktop shell

Tauri 2.0 reached stable on October 2, 2024, with first-class mobile (iOS & Android) targets, an ACL/capabilities/scopes permissions model, and a redesigned IPC layer that uses custom protocols instead of serializing every message through the WebView's postMessage[?]. The new tauri::ipc::Channel API streams data (file chunks, log lines, download progress) from Rust to the frontend with much lower overhead than the v1 IPC[?].

Architecturally, Tauri uses tao for window management and WRY for the WebView abstraction[?]. The WebView is the OS-native one — WKWebView on macOS, WebKitGTK 4.1 on Linux (Ubuntu 22.04+ / Debian 12+), and WebView2 on Windows (out of scope for v1.0)[?]. Tauri ships under MIT-or-Apache-2.0[?].

The full set of features relevant to a Docker-Desktop-shaped app — native menu bar, system tray icon and menu, signed/notarized installers, a sidecar plugin for embedding external binaries, file-system and process plugins — is first-party and documented[?][?][?][?]. 

// Tauri 2 — typed command using the Channel API to stream log lines.
use tauri::ipc::Channel;
use serde::Serialize;

#[derive(Clone, Serialize)]
#[serde(rename_all = "camelCase", tag = "event", content = "data")]
enum LogEvent<'a> {
    Line { stream: &'a str, text: &'a str },
    Closed,
}

#[tauri::command]
async fn tail_logs(server: String, on_event: Channel<LogEvent<'_>>) {
    // ... read from mcpd over UDS and stream lines ...
    on_event.send(LogEvent::Line { stream: "stdout", text: "hello" }).ok();
    on_event.send(LogEvent::Closed).ok();
}

Leptos — the Rust-WASM frontend

Leptos is a fine-grained reactive Rust web framework that compiles to WebAssembly and (optionally) to a native server binary for SSR[?][?]. The mental model is closest to SolidJS: components are functions that run once and set up reactive subscriptions; signal updates patch only the affected DOM nodes — no virtual DOM[?].

Leptos 0.7 (late 2024) introduced a statically-typed view tree — every view has a concrete Rust type, with AnyView as the type-erased escape hatch — which improves error messages and rendering performance but raises the compiler-error learning curve[?]. Leptos 0.8 (2025) focused on iterating on the 0.7 model and compile-time ergonomics, including a --cfg=erase_components dev-mode flag that significantly improves incremental compile times[?]. As of 2026, Leptos is at 0.8.x stable with 0.9 in alpha[?].

Leptos is MIT-licensed[?]. Benchmark comparisons consistently rank Leptos near vanilla JavaScript and meaningfully ahead of React on the standard JS framework benchmark[?]. 

// Leptos 0.8 — a server-list component with fine-grained reactivity.
use leptos::prelude::*;

#[component]
pub fn ServerList() -> impl IntoView {
    let servers = Resource::new(|| (), |_| async move {
        // Calls into a Tauri command or fetches mcpd's HTTP bridge directly.
        invoke::<Vec<Server>>("list_servers", &()).await
    });
    view! {
        <Suspense fallback=move || view!{ <p>"loading…"</p> }>
            <ul>{move || servers.get().map(|list| list.into_iter()
                .map(|s| view!{ <li>{s.name}</li> }).collect_view())}</ul>
        </Suspense>
    }
}

How they fit together (build pipeline)

The first-party Tauri guide for Leptos[?] states up front: "Tauri doesn't officially support server based solutions, so use SSG." In practice that means Leptos in CSR (client-side rendering) mode — the WASM bundle loads inside the Tauri WebView and renders the entire UI client-side. SSR would imply running an HTTP server inside the Tauri shell, which Tauri explicitly does not endorse for desktop apps.

The build pipeline has two viable shapes:

  1. Trunk (recommended by Tauri docs) — bundles the Leptos WASM crate, copies assets, serves on a dev port. Tauri's beforeDevCommand calls trunk serve; devUrl points to http://localhost:1420[?].
  2. cargo-leptos — Leptos's first-party build tool; coordinates server and client builds, has Tailwind/SASS support and a --hot-reload mode[?][?]. Slightly more opinionated; less common in Tauri setups because of its SSR-leaning workflow.

For MCP Manager, Trunk + CSR is the path of least resistance. The Tauri config wires withGlobalTauri = true so the Leptos WASM can reach window.__TAURI__ via wasm-bindgen to call typed Tauri commands[?].

Important pinning note: the Tauri docs page for Leptos is, as of 2026, still written against Leptos 0.6 while the framework itself is on 0.8.x[?][?]. The community example repos (e.g. michalvavra/tauri-leptos-example[?]) and the ForgeStream walkthrough[?] bridge the gap, but expect to cross-reference.

Dev loop and hot reload

The honest summary: you do not get JavaScript HMR speeds with Leptos. The framework documentation itself acknowledges this — incremental Rust+WASM rebuilds are typically 3–4 seconds for non-trivial changes; CSS/SASS reloads are sub-second; component-structure changes via cargo leptos watch --hot-reload can patch in place without a full page reload in many cases[?][?].

For an app shaped like MCP Manager — frequent style/layout iteration on a server-list table, log viewer, and secrets editor — the practical workflow is:

  • Style and layout tweaks: instant via CSS/SASS hot-reload.
  • Reactive logic tweaks: 1–2s when components are small, 3–5s when changing widely-used types.
  • Schema changes (shared serde types in the core crate): full rebuild of both the WASM and Rust-side Tauri command surface — can hit 10–30s on a cold cache.

This is meaningfully slower than Tauri+TS/React (where Vite HMR is sub-100ms), and the gap will not close with optimization — it is fundamental to compiling Rust to two targets.

Packaging on macOS and Linux

PlatformBundleSigningNotes
macOS .app inside .dmg[?] Developer ID + notarization, automated via APPLE_API_KEY / APPLE_API_ISSUER env vars[?] Universal binary (aarch64 + x86_64) supported but doubles bundle size. Notarization adds 30–90s to CI; certificates expire every 5 years — diary it.
Linux .AppImage and .deb out of the box[?][?] No signing required by default; AppImage supports gpg signing .rpm requires a third-party action. AppImage embeds WebKitGTK runtime dependencies as system libs — works on most distros; expect a Flathub manifest if you want sandboxed install.

Installer sizes for real-world Tauri apps land in the 600 KB – 10 MB range for the installer shell[?]. With Leptos WASM, a non-trivial log-viewer + secrets editor + server list will likely push the installer to 8–15 MB unzipped — still ~10× smaller than an equivalent Electron app[?].

Ecosystem and prior art

Tauri itself is in robust shape in 2026. The awesome-tauri index lists hundreds of production apps[?]; commonly-cited shipping users include Ariadne (Git client), LumenTrack (crypto tracker), Whispering (speech-to-text), Watson.ai (meeting tools), and 1Password 8 as an early flagship adopter[?]. The bulk of these use a TS/React or TS/Vue frontend.

Leptos itself is also in good shape for full-stack web; the maintainers state the APIs are "basically settled" and breaking changes within minor versions are limited[?]. A growing pool of SSR-web apps use Leptos in production.

The Tauri+Leptos intersection is the soft spot. There are working examples (michalvavra/tauri-leptos-example[?], the ForgeStream walkthrough[?], the DEV tutorial[?]) and small commercial apps, but there is no widely-known mass-market consumer app on this specific combination. You will not be following a beaten path; you will be one of the first 100.

For typed Rust↔WASM IPC, the community has converged on TauRPC — a typesafe IPC layer that generates matching Rust and TypeScript bindings; with Leptos you skip the TS generation and use the Rust bindings directly[?].
