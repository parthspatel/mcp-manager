Interactive ranking matrix

Nine host applications scored 0–5 on eight capability criteria. Drag the weight sliders to see the ranking change live. Click any score's evidence link to jump to the supporting citation. Scoring rubric is documented below the matrix.

Scoring rubric (0–5)

ScoreMeaning
0Not supported / not applicable
1Theoretically possible but undocumented; requires user workarounds
2Basic, with significant friction (e.g. plaintext only, manual restart only)
3Works, but with caveats (e.g. only via UI, only via OAuth, only on one OS)
4First-class documented support
5Best-in-class; sets the bar for the ecosystem

Criterion definitions

Config UX

How easy is it to discover, edit, and validate the config? Includes auto-open from settings, JSON-schema validation, error highlighting, and CLI-driven add flows.

Transport coverage

Score reflects support for stdio + Streamable HTTP (current spec) and graceful handling of deprecated SSE.

Secrets handling

Does the host avoid forcing plaintext secrets? OS keychain, secret prompts, encrypted storage are all credited.

Lifecycle management

Process supervision: restart on crash, graceful shutdown, per-server timeouts, hot reload of config.

Error visibility

Are connection errors, exit codes, and stderr surfaced in-app, or buried in tail-able log files?

Isolation

Sandbox flags, capability scoping, network constraints. Currently sparse across the ecosystem.

Multi-server scaling

How well does the host run 10+ MCP servers? Includes the documented Claude Desktop crash with 2+ servers and Windsurf's 100-tool cap.

Portability

Schema compatibility with other hosts. Hosts using mcpServers get a boost; outliers (context_servers, servers, extensions) get penalized.

Reading the matrix

The default weights prioritize secrets handling (0.18), config UX (0.16), lifecycle management and transport coverage (0.14 each). The MCP Manager's job is to lift every host up to the bar set by the best-in-class capability on each row, so the highest-scoring hosts indicate where the bar already is, while the lowest-scoring hosts indicate where the most value can be added by external tooling.

The matrix is descriptive, not predictive — it scores hosts on what they ship today (as of 2026-05-24), not on what their roadmaps suggest. Where evidence is thin (e.g. Goose's HTTP support varies by version, Zed's transport list is partly inferred), the score sits in the middle band (2–3) rather than being inflated.
