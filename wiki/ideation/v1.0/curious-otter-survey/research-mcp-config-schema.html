Schema comparison: command/args/env vs url/headers

The MCP spec is prescriptive about the wire protocol — JSON-RPC over a transport — but says nothing about how a host should configure a server. Every host has invented its own wrapper. This page lays the JSON side-by-side.

What is universal

The MCP specification defines two standard transports — stdio and Streamable HTTP — and requires JSON-RPC framing on both. Every host surveyed encodes the same conceptual server definition in JSON or YAML using these four parts:

ConceptStdio fieldsRemote fields
How to start itcommand, argsurl
How to authenticate / parametrizeenvheaders (or OAuth)
Working directorycwd (rare)n/a
IdentityMap key (server name)Map key (server name)

Host-specific schema extensions

Approval governance

Cline's autoApprove array lists tools that should bypass per-call approval; Claude Code uses settings.json permissions.deny; VS Code adds sandboxEnabled. There is no shared model.

Secret prompting

Only VS Code's inputs array and Claude Desktop's DXT user_config ship a first-class "ask the user for a secret on install and store securely" experience.

Lifecycle controls in-config

Claude Code's per-server timeout (milliseconds), alwaysLoad, and global MCP_TIMEOUT env var are unique. Cline exposes restart and timeout via UI. Other hosts hardcode their lifecycle.

Variable expansion

Inconsistent: Claude Code ${VAR}/${VAR:-default}; Cursor ${env:NAME}, ${workspaceFolder}; Windsurf ${env:VAR} + ${file:PATH}; Continue ${{ secrets.X }}; Claude Desktop has no expansion at all (literal strings only).

What the spec actually mandates

The MCP spec is silent on configuration format. It only mandates:

  • JSON-RPC framing on both transports.
  • For stdio: newline-delimited messages on stdin/stdout, no stdout pollution, logs only to stderr.
  • For Streamable HTTP: a single endpoint that accepts both POST and GET, with an optional Mcp-Session-Id header for session management and an MCP-Protocol-Version header on every request.
  • OAuth 2.0 discovery via /.well-known/oauth-protected-resource (RFC 9728) and /.well-known/oauth-authorization-server (RFC 8414) for remote servers requiring auth.

Everything above the wire protocol — schema, file location, env handling, lifecycle, secrets, sandboxing — is host-invented and inconsistent. That is the primary observation an MCP Manager needs to absorb.
