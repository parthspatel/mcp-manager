Recommendation — Client tooling stack for the MCP Manager

This is the only page in the stream where opinions live. The argument: pick the boring, well-trodden default for the CLI and TUI; treat the GUI as a place where the choice is genuinely live and where Tauri 2 is the safest landing pad while we learn what users actually need.

TL;DR

  • CLI: clap (derive feature) + owo-colors + indicatif + tabled + clap_complete. Near-default
  • TUI: ratatui + crossterm, components pattern by hand initially, escalate to tui-realm only if multi-pane state management becomes painful. Near-default
  • GUI: Tauri 2 with a Rust-WASM frontend (Leptos preferred, Dioxus acceptable). Could-flip-on-evidence — egui or Slint if Tauri's three-WebView story bites us, iced if COSMIC compatibility becomes strategically important.
  • Shared mcp-client crate: wire types, error enum, config loader, daemon transport, JSON/YAML serializers, SecretStore trait, tracing setup. No UI dependencies.

CLI — Near-default

ConcernChoiceWhy
Argument parsingclap with derive featureEcosystem consensus (75M+ downloads, every CLI tutorial assumes it) and the maintainers themselves recommend the derive API for new code . We can fall through to builder for any subcommand that needs runtime introspection.
Shell completionclap_complete via a hidden completions <shell> subcommandOne-line generator; supports Bash/Zsh/Fish/Elvish/PowerShell, plus Nushell via clap_complete_nushell .
Colorizationowo-colorsZero-allocation, no_std-friendly, drop-in for colored; endorsed by Rain's recommendations . We honor NO_COLOR + TTY detection per the CLI Guidelines .
Table outputtabledDerive macro maps directly onto our ServerSummary-style structs in mcp-client; cleaner ergonomics than comfy-table's builder API for our typed rows .
Progress reportingindicatif + tracing-indicatifDe facto standard at 90M+ downloads; MultiProgress for concurrent operations; tracing bridge keeps progress and logs from fighting .
Machine outputserde_json / serde_yaml direct from mcp-client typesMirrors kubectl -o json / gh ... --json . Same types are reused by GUI "Copy as JSON" actions.
Command shapeDocker-style noun-verb with at least one nesting level (mcpm server up, mcpm config set)Familiar to operators of docker/kubectl/gh; clap derive's subcommand-enum pattern maps onto this cleanly .

See research-client-tools-cli.html for the full enumeration of alternatives we considered, and the CLI ranking matrix for sensitivity.

TUI — Near-default

ConcernChoiceWhy
FrameworkratatuiActive maintained successor to tui-rs; powers the apps the MCP Manager TUI most directly resembles — bottom (live process monitor), gitui (component-pattern TUI), yazi (async-first) .
BackendcrosstermThe documentation explicitly recommends it; Windows + macOS + Linux + WSL out of the box; async event stream via the event-stream feature . termion is Unix-only and disqualified ; termwiz is for wezterm-specific features we don't need .
ArchitectureComponents pattern by hand (per ratatui's components template) with a tokio::select! loop over EventStream + daemon-event mpscThe pattern gitui uses; gives us focus stack and message routing without committing to tui-realm's lifecycle .
Optional escalationtui-realm if multi-pane state management gets messyAdds an Elm-style component model with explicit messaging; pays off when many independent panes need their own state machines . Defer until proven necessary.
Async runtimetokioAlready chosen by Stream 3 / Stream 4; crossterm::event::EventStream and the daemon transport both speak tokio futures .

The TUI's "happy path" is intentionally identical to gitui's: a draw loop, an event multiplexer, components that own their state. We don't take dependencies on tui-realm or cursive until we have evidence the bare pattern isn't holding up.

GUI — Could-flip-on-evidence

Primary recommendation: Tauri 2 with a Rust-WASM frontend.

ConcernChoiceWhy
App shellTauri 2Stable since Oct 2024 with ACL-based permissions, custom-protocol IPC, and the typed Channel API for streaming events (logs, status updates) from Rust to the UI . Installers are typically 600 KB – 10 MB vs Electron's 80–150 MB . Accessibility, IME, text shaping all inherited from the system WebView — solving problems most pure-native Rust toolkits have not yet solved .
Frontend frameworkLeptos (preferred) or DioxusBoth compile to WASM and are first-party templates in create-tauri-app . Leptos's fine-grained reactivity is closer to what makes Tauri's IPC overhead invisible; Dioxus is a reasonable second if the team prefers a React-style mental model.
Mobile / web targetDeferred but not foreclosedTauri 2 ships iOS + Android support; Leptos compiles to web. A v1.x mobile companion is on the table without a rewrite .
IPC pattern#[tauri::command] + tauri::ipc::Channel for streamsThe v2 IPC uses custom protocols (not postMessage string serialization) and the channel API is purpose-built for log-tail / event-watch .
ThemingPer-OS CSS palette + the system's accent color via tauri::window::Window::themeDark mode for free; native title bar; the GUI defers to the OS rather than imposing its own look.

Why not pure-native? Three reasons. (1) The boringcactus 2025 survey concluded that of 43 Rust GUI libraries tested, 94% failed a minimal "label + input + screen-reader + IME" baseline; the four that passed are Slint, egui, Dioxus, and Windows-only WinSafe . (2) Slint's strongest pure-native showing comes with a GPL-or-paid license that we don't want to pay or be infected by . (3) egui is excellent for tool-class apps (Rerun) but explicitly disclaims native look and stability across upgrades . None of these are disqualifying for v2; they are for v1.

Could-flip-on-evidence triggers:

  • If WebKitGTK incompatibilities on Linux create a real support burden, evaluate egui + eframe as the swap — it's the lowest-risk pure-native pivot since AccessKit is integrated and the team behind it ships a major production app (Rerun) .
  • If we ever need to integrate with COSMIC desktop or System76 hardware partnerships, iced becomes strategically interesting — at the cost of accepting its weaker accessibility story .
  • If we are willing to pay for Slint's commercial license and want the strongest pure-native a11y + embedded story, Slint is the better long-run answer .
  • GPUI, Freya, Xilem, Makepad — watch list, not pick list, for v1.0 .

Shared mcp-client crate composition

One crate, three consumers (CLI / TUI / GUI). It depends on the Stream-4 protocol crate but knows nothing about clap, ratatui, or any GUI framework. Concretely:

# crates/mcp-client/Cargo.toml — recommended composition.
[dependencies]
mcp-protocol = { path = "../mcp-protocol" }   # from Stream 4
serde = { version = "1", features = ["derive"] }
serde_json = "1"
serde_yaml = "0.9"
thiserror = "1"
tokio = { version = "1", features = ["sync", "rt", "io-util", "net"] }
tracing = "0.1"
tracing-subscriber = { version = "0.3", features = ["env-filter", "fmt"] }
keyring = "3"            # OS keyring for SecretStore
zeroize = "1"            # for Secret<T> memory-safety wrapping
directories = "5"        # XDG-style config paths
figment = { version = "0.10", features = ["toml", "env"] }  # layered config
futures = "0.3"          # Stream traits for log tail / event watch

What lives inside:

  1. Wire types: ServerSummary, ServerStatus, ConfigDiff, StatusKind — all serde-derived.
  2. Error model: a ClientError enum + impl From<ClientError> for i32 for CLI exit codes.
  3. Config loader: XDG paths + env override + file; Config::load_with_overrides(&CliFlags).
  4. API client: Client::connect(&Path), list_servers, start_server, tail_logs (Stream), watch_events (Stream).
  5. SecretStore: trait + KeyringStore default; CLI/TUI/GUI each drive the prompt UX they need.
  6. Output formatters: format::json, format::yaml, format::plain — table formatting stays in the CLI crate.
  7. Tracing setup: logging::init_for_cli, init_for_tui, init_for_gui — feature-flagged so each consumer compiles minimal code.

What stays OUT: any clap code, any ratatui widget, any indicatif bar, any tabled renderer, any GUI framework, any color crate. The compile-to-WASM heuristic: if mcp-client stops building for wasm32-unknown-unknown, something snuck in that shouldn't have. See research-client-tools-shared.html for the full boundary discussion.

Volatility — what could flip the GUI choice

The Rust GUI ecosystem is moving faster than the CLI or TUI ecosystems, and almost everything below was true at a different time:

  • Iced 1.0 arrives in 2026 and brings accessibility to parity — that materially weakens the "WebView for free a11y" argument .
  • Slint relicenses or our licensing constraints change — Slint becomes the obvious pick on technical merits .
  • GPUI hits 1.0 with Windows parity — but this is at least a year out and we are not the right early adopter for it .
  • WebKitGTK fragmentation becomes painful for our Linux users — pivot to egui or Dioxus desktop and absorb the a11y/IME cost .
  • The team experiences Tauri's two-codebase build as friction — Dioxus desktop is the cleanest pure-Rust escape hatch with the same WebView model .

The CLI and TUI choices have effectively no volatility: clap and ratatui+crossterm are stable consensus picks with active maintenance and large production user bases . They should be revisited only if either crate is materially abandoned, which is not a 2026 risk.
