Stream summary in one paragraph

Of seven candidate sync strategies surveyed across the dotfile and config-management ecosystem (chezmoi, home-manager, dotter, mise, kustomize, Ansible, Renovate's customManagers), the only one that simultaneously preserves hand-edits, stays idempotent, surfaces conflicts honestly, and works on every supported tool's file format is the managed-block pattern — a fenced region marked with BEGIN MCP-MANAGER MANAGED BLOCK / END MCP-MANAGER MANAGED BLOCK rewritten in place. Tools whose config format cannot embed comments (pure JSON) get a sibling-file projection (.mcp.json companion) instead. Cross-tool extensibility is solved by a TOML-based toolchain.toml spec that ships in $XDG_CONFIG_HOME/mcp-manager/toolchains/ and is loaded at daemon start; users add a new tool by writing one file. Tier-1 (auto-detected, projected by default with user consent): Claude Code CLI, Codex CLI, VS Code, Cursor, Zed, the JetBrains family. Tier-2 (supported but opt-in): Windsurf, Continue, Cline, Goose, LibreChat, Claude Desktop. Open WebUI is explicitly excluded because its MCP integration runs through a separate proxy (MCPO) that breaks our projection invariants .
