MCP Manager — v1.0

Docker-style management for MCP servers on macOS & Linux. A Rust daemon (mcpmanagerd) supervises a few dozen MCP server processes, while a CLI (mcpm) and a TUI give developers one-shot and interactive control. mcpmanagerd manages the canonical state, isolates each server, projects configs into the developer's editors (Claude Code, Cursor, Zed, JetBrains, VSCode…), and keeps secrets out of plaintext files.

macOS + Linux only Apache 2.0 No telemetry, ever 10s of MCPs scale target

What is MCP Manager?

The Model Context Protocol (MCP) makes it possible for AI assistants like Claude, Cursor, and Zed to call out to external tools (a GitHub MCP, a filesystem MCP, a SQL MCP, etc.). MCP servers are processes you run on your machine; each AI client connects to them over stdio or HTTP.

In practice, developers end up with the same MCP server configured separately in each of their AI tools, with secrets in plaintext in each editor's config file, no central process supervision, and no consistent way to install, update, or manage them. MCP Manager is "Docker for MCP servers": one daemon (mcpmanagerd) supervises the actual server processes; one canonical config (TOML) lives in ~/.config/mcp-manager/; the manager projects that config into each editor's expected format so the editors keep working. Secrets stay in the OS keychain.

For a developer, the experience is: 

mcpm install github           # discover + install an MCP server from a registry
mcpm secret set GITHUB_TOKEN  # interactive prompt, written to OS keychain
mcpm tui                      # lazygit-style TUI for status, logs, edits
mcpm test github              # health check
mcpm logs --follow github     # tail a specific server's logs

…and their existing editors (Claude Code, Cursor, Zed, etc.) just see the MCP server they expect, with no plaintext secrets in their configs.

v1.0 scope (in & out)

v1.0 ships

  • mcpmanagerd daemon with full process supervision (restart, OOM, audit log, tail API)
  • mcpm CLI — install, search, test, logs, secret, registry, project, update, init, uninstall
  • mcpm tui — lazygit-style interactive client
  • Toolchain projection for Tier-1 tools (incl. JetBrains XML)
  • Secrets via OS keychain + env-var passthrough
  • 3 baked-in registries (official, GitHub, Docker)
  • Health check (mcpm test)
  • mdbook docs in repo
  • Code-signed macOS binaries; minisign-signed Linux tarballs

Deferred to v1.1+

  • GUI — Actix+Askama pre-decided, see shootout
  • Vault providers (1Password, Bitwarden, Vault, Doppler, …)
  • Secret rotation + TTLs
  • mcpm import-from for existing editor configs
  • Observability (Prometheus, OpenTelemetry)
  • Backup / restore / state portability
  • Resource limits beyond memory (CPU, disk, network)
  • Curated community toolchain registry
  • Plugin / extensibility SDK
  • Biometric (TouchID) keychain reads — best-effort in v1.0
  • See future features for full list

Never (permanent project decisions)

  • Windows support
  • Telemetry / phone-home of any kind
  • Plaintext-secrets-in-config fallback (use env-var passthrough instead)
