UX principles

The "OBSESSED about UX" mandate, made operational:

Discoverability over memorization

The TUI's bottom hint bar is always on and context-aware. The CLI's help text shows real examples, not just flag descriptions. ? in the TUI shows the full keymap modal. Users should never have to guess what's available.

Idempotent everywhere

Re-running mcpm init is a no-op + summary. Re-running mcpm install foo when foo is already installed is a no-op + summary. Re-running mcpm secret set X overwrites cleanly. Replay-safety is a UX feature; users don't have to remember whether they already did the thing.

Reversible by default; destructive ops are explicit

Start, stop, restart, edit: no confirmation. Delete a server: y/N prompt. Wipe all canonical state: type literally WIPE. Purge a secret: type the secret name. Asymmetry on purpose — friction matches reversibility.

Show what you're about to change

mcpm update shows a diff before applying. mcpm install reports which editor configs were touched. mcpm uninstall lists exactly what will be removed before doing it. The user is never surprised after the fact.

Non-interactive everything

Every interactive flow has CLI flags that fully replace it. mcpm init --defaults -y sets up zero-input. mcpm install foo --version=^0.4 skips the version prompt. CI / Nix / scripts shouldn't fight the tool.

Trust the user's editor

When the user edits a config, the TUI spawns $EDITOR. We don't reinvent text editing. The same goes for diffs (use git diff if available), prompts (use the TTY), and pagination (use $PAGER).

CLI surface — all subcommands

The CLI is the primary surface for power users + automation + scripting. Every interactive flow has a non-interactive equivalent.

Universal flags (all commands)

  • --verbose / -v — extra diagnostic output
  • --quiet / -q — suppress non-essential output
  • --json — machine-readable output (where applicable)
  • --no-color — disable color output (also respects NO_COLOR env)
  • --config-dir <path> — override ~/.config/mcp-manager

TUI layout + behaviors

Single-screen, lazygit/k9s style. Three concern-grouped panes on the left (Servers / Toolchains / Secrets), contextual right pane (logs / details / edit).

Pane focus + key affordances

  • The focused pane has a highlighted border. Single-character actions in the hint bar apply to the focused pane's selected entity.
  • The hint bar is context-aware: when a server is stopped, s appears; when it's running, d appears instead. Inapplicable affordances are hidden.
  • Pane focus cycles with Shift+Tab. Tab alone cycles log streams in the right pane.

Log multiplexing

  • Tab order in the right pane: server → mcpmanagerd → audit → combined → server → …
  • Each tab maintains its own scroll position.
  • Switching server in the left pane carries the tab forward (audit on github → switch to filesystem → still on audit, but for filesystem).
  • Follow mode on by default; f toggles. When paused, scrollback works without losing new entries (they're buffered).
  • / within the log pane greps the current buffer; n/N next/previous match; Esc clears.

Editing

  • e on the focused entity opens $EDITOR with that entity's TOML stanza extracted to a temp file.
  • On editor save: validate via config.validate → atomic write back → audit-log → mcpmanagerd reload.
  • On validation failure: re-enter TUI with a modal showing the error + offending line; temp file preserved so the user can retry with e again.

Confirmation patterns

ActionConfirmation
Start / stop / restart serverNone (reversible)
Edit canonical configNone (edit is non-destructive until save; validation gates the save)
mcpm updateDiff shown; single Enter to apply; -y skips
Delete a server configy/N prompt
Purge a secretType the secret name (matches gh repo delete paranoid pattern)
Wipe all canonical stateType literally WIPE

Mouse support

  • Click to focus a pane; click to select an entity; double-click = drill into detail (same as Enter).
  • Mouse wheel scrolls the focused pane (including log scrollback).
  • Right-click is unbound in v1.0 — no context menus yet.
  • Option/Alt bypass: holding Option (macOS) / Alt (Linux) while click-dragging suspends mouse capture so native terminal text selection works for copy/paste. Documented in the help modal.

Reserved for future versions

Intentionally unbound in v1.0 to preserve muscle memory when v1.x adds features:

Config files

Three persistent files. All TOML. All hand-editable. mcpmanagerd reconciles on next read.

User-scope config (~/.config/mcp-manager/config.toml)

# MCP Manager · user-scope canonical config
# Hand-edit OR use `mcpm` CLI. mcpm reconciles both.

[mcpmanagerd]
audit_retention_days = 90
log_ring_buffer_mb   = 10
service_register     = true

[server.github]
registry  = "official"
package   = "github-mcp"
version   = "^0.4"
isolation = "devenv"
secrets   = ["GITHUB_TOKEN"]

[server.github.env]
GITHUB_OWNER = "anthropic"

[projection.claude-code]
enabled = true
scope   = "user"

[registry.official]
url = "https://registry.modelcontextprotocol.io"
# pubkey verified via baked-in trust.toml; no per-source key here

[registry.corp]
url        = "https://internal.example.com/mcpm-registry"
signed_by  = "RWQabc…"
auth       = { type = "bearer", secret = "CORP_REGISTRY_TOKEN" }

Project-scope config (<repo>/.mcp-manager.toml)

# MCP Manager · project-scope canonical config (checked into repo)

[mcpm]
inherit          = "all"        # "all" | ["server1", "server2"] | "none"
min_mcpm_version = "1.0"
description      = "ACME data pipeline tooling"
test_on_update   = true

[server.acme-db]
registry  = "official"
package   = "postgres-mcp"
version   = "^0.3"
isolation = "devenv"
secrets   = ["ACME_DB_URL"]

[server.github]                 # project-local override of user's github
allowed_paths = ["/work/acme-project"]
# Other keys (registry/package/version/secrets) inherited from user config.

Per-project layering — the three modes

  • inherit = "all" (default) — project servers OVERLAY user servers. Same-name = project wins.
  • inherit = ["s1", "s2"] — allowlist; only the named user servers are pulled in.
  • inherit = "none" — full isolation (venv-style). For privacy-sensitive client work.

[server.<name>] disabled = true in a project config hides an inherited user-level server in that project only.

version  = 1

Onboarding flow

From the onboarding agent's recommendation: mcpm init is a thin scaffolder (not a doctor). Modeled on aws configure defaults + terraform init staged output + npm init -y skip flag. Idempotent; -y skips confirmations; --defaults accepts every default.

Lucky-day interactive (~30 seconds)

$ mcpm init
   What's your name? [Parth Patel]   ←
   Scope: user or project? [user]   ←
   Detected: Claude Code, Cursor, Zed. Project into all three? [Y/n]   ←
   Detected: Docker. Enable Docker MCP Catalog as a registry? [y/N]   ←
   Register mcpmanagerd with launchd as a background service? [y/N]   ←
   ✓ Wrote ~/.config/mcp-manager/config.toml
   ✓ Wrote ~/.config/mcp-manager/trust.toml
   ✓ Projected canonical state into 3 editor configs
   ✓ Refreshed trust.toml (4 registry pubkeys, valid until 2027-…)

   Next: `mcpm install <server>` to add an MCP server.

Full non-interactive (CI / Nix / scripted)

$ mcpm init --defaults -y
   ✓ Initialized (user scope, default projections, no Docker, no service-register).

Project-scope (in a repo)

$ cd /work/acme-project
$ mcpm project init

Service-manager registration (first launch)

If service_register=true in onboarding, mcpm runs:

  • macOS: launchctl bootstrap gui/$UID ~/Library/LaunchAgents/dev.mcp-manager.mcpmanagerd.plist
  • Linux: systemctl --user enable --now mcpmanagerd.service

Audit-logged as service.register. Reversed by mcpm uninstall (audit: service.unregister).

Error UX

Errors are a UX surface, not forensics. Every error tells the user (1) what happened, (2) why, and (3) what to do next.

Error taxonomy

CodeMeaningTypical fix
E_SECRET_MISSINGServer requires a secret that isn't in the keychain or env.Run mcpm secret set <NAME> (the exact command is printed).
E_SERVER_OOMServer was killed for OOM. Memory limit hit or system pressure.Raise [server.<name>].memory_max_mb or investigate leak via mcpm logs <name>.
E_SERVER_FAILEDServer crashed too many times in the restart window. mcpmanagerd stopped retrying.Investigate logs, then mcpm restart <name> to clear failed state.
E_CONFIG_INVALIDCanonical config failed validation (TOML parse, schema, type, or constraint).Error message points at line/column. Re-open with mcpm config edit or revert.
E_CONFIG_CONFLICTCanonical config changed on disk while a concurrent config.put was in flight.TUI re-reads + offers to merge or discard. CLI: re-run command.
E_REGISTRY_UNREACHABLERegistry network fetch failed (DNS, TLS, 5xx).Check connectivity. Cached index continues to work for mcpm search.
E_REGISTRY_SIGFAILRegistry index signature didn't verify. Possible compromise OR rotated key.Run mcpm registry verify. Refresh trust manifest. Report if persistent.
E_SPEC_UNSUPPORTEDServer advertises an MCP spec version mcpmanagerd's allow-list doesn't accept.Override with [server.<name>].spec = "…" if you trust the server, or wait for an mcpmanagerd update.
E_PROJECTION_DRIFTAn editor config file's managed-block was hand-edited; projection refuses to overwrite blind.mcpm projection diff <tool> shows the conflict. Re-sync with --force after review.
E_PROJECT_UNTRUSTEDProject config exists but wasn't trust-granted in this session.Run mcpm project allow (prompts to review) or mcpm project allow --force.
E_KEYCHAIN_UNAVAILABLEOS keychain service (libsecret / Keychain Services) isn't reachable.Linux: install gnome-keyring or kwallet. Use --from-env as escape hatch.
E_DAEMON_VERSIONmcpmanagerd version is older than project's min_mcpm_version.Update mcpmanagerd via curl installer or nix flake update.

Error presentation — CLI

$ mcpm start github
   ✗ Failed to start github (E_SECRET_MISSING)

   The server requires a secret that isn't available:
     GITHUB_TOKEN  (not in keychain, not in environment)

   To fix:
     $ mcpm secret set GITHUB_TOKEN

   Then re-run:
     $ mcpm start github

Error presentation — TUI

Errors appear as modal overlays on the TUI. The modal has: error code (top-left), one-line title, multi-line explanation, suggested-fix command (copy-able with y), Esc to dismiss, l to jump to relevant logs. A small ✗ badge appears next to the affected entity in the left pane until cleared.

What we deliberately don't do

  • Silent fallbacks. If a secret is missing, we refuse to spawn — never spawn with a missing-value fallback. Same for unsigned registries (unless --accept-unsigned), failed projections, etc. Loud refusal beats quiet wrong-state.
  • Stack traces in user-facing output. Stack traces go to mcpm logs --daemon. The error UX is the curated subset.
  • Generic "an error occurred" messages. Every error has a code, an explanation, and a fix.

Help & docs

mcpm help

Rich help built into the binary. Every subcommand's help text includes:

  • One-line purpose
  • Full flag list (with defaults)
  • At least 3 worked examples with real arguments (not <ARG>)
  • "See also" links to related subcommands
  • Pointer into the mdbook docs for deeper reading
$ mcpm help install
   mcpm install <source>  —  install an MCP server from a registry

   USAGE:
     mcpm install <source> [--scope user|project] [--name <alias>] [--runtime <rt>]

   FLAGS:
     --scope <scope>        user (default) | project
     --name <alias>         override the server name in canonical config
     --runtime <runtime>    devenv (default) | docker | podman | uvx-npx | none
     --accept-unsigned      install without minisign verification (audit-logged)
     --dry-run              show what would happen; write nothing

   EXAMPLES:

     # Install latest 0.4.x of the official github MCP, user-scope
     $ mcpm install official/github-mcp@^0.4

     # Install at a specific version, project-scope, isolated under docker
     $ cd /work/acme-project
     $ mcpm install acme-corp/internal-mcp@=0.2.1 --scope project --runtime docker

     # Install from a private registry under an alias
     $ mcpm install corp/sql-helper --name local-sql

   SEE ALSO:
     mcpm search    discover servers across registries
     mcpm test      verify a newly-installed server is healthy
     mcpm registry  manage upstream registries

   DOCS:
     https://docs.mcp-manager.dev/cli/install

mdbook docs in repo (docs/)

  • Source: docs/src/*.md. Built with mdbook build. Deployed to docs.mcp-manager.dev.
  • Single source of truth for non-CLI documentation: architecture overview, tutorials, recipes, FAQ.
  • Versioned per-release: docs.mcp-manager.dev/v1.0/, v1.1/, etc.
  • Searchable via mdbook's built-in client-side search.

Accessibility commitments

  • Color is never the only carrier of information. Status indicators use color AND glyph (● running, ○ stopped, ⚠ failed). Severity in logs uses color AND prefix ([ERR], [WARN]).
  • NO_COLOR env var respected. Also $COLORTERM for capability detection.
  • 8-color palette as the base; 256-color or truecolor enhancement when available.
  • Configurable theme via ~/.config/mcp-manager/tui-theme.toml. Bundled themes: default, high-contrast, monochrome.
  • Keyboard-only operation always works. Mouse is enhancement, never required.
  • Screen-reader output in v1.0 is best-effort — modern terminals + ratatui have decent support, but we don't claim WCAG conformance. v1.x may add an explicit screen-reader mode.
  • No flashing / strobing in the TUI (per WCAG seizure guidance, even though we don't claim conformance).
