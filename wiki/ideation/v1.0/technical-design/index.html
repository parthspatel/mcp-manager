How to read this sub-wiki

Three nested layers. Each layer compresses the one below it.

  1. Master synthesis.html — the consolidated detailed design. Per-crate deep dive (11 crates), per-flow deep dive (5 flows: install, exec, secret-set, crash-restart, TUI startup), per-facet pull-ups, consolidated open questions (12), and the Diffs against v1.0 spec table. Read this for the conclusions.
  2. Per-facet overview.html (5 total) — one synthesis pass per facet (backend · frontend · devops · security · ux). Each lists points of agreement, points of disagreement, per-component decisions with rationale, open questions, and a live tunable ranking matrix. Read these for the reasoning behind each synthesis decision.
  3. Per-agent essays (25 total — 5 stances × 5 facets). Each agent commits to a single deliberately-incompatible angle (e.g. tokio pragmatist, red team, vim power user) and writes a self-contained essay with three sections: #thoughts (initial reaction), #arguments (debate points against the other 4 stances in the same facet), #design (concrete proposal with schemas + diagrams + code snippets). Read these only when you want to hear a specific stance defended at length.

The locked v1.0 decisions (drop Windows, no telemetry, curl+Nix distribution, 11-crate workspace, etc.) were inputs for all 25 agents. Nothing in this subtree re-opens the lockdown.

The five facets

Backend 5 stances

Daemon, supervisor, protocol crate, registry, secrets, projector, logs, trust. The most complex facet.

  • tokio-pragmatist — idiomatic async, tower layers
  • systems-veteran — sans-I/O cores, state machines
  • library-author — tiny mcpm-protocol, semver
  • kernel-hacker — cgroups, RLIMITs, jetsam
  • boring-tech-defender — line-delimited JSON, ship

Frontend 5 stances

CLI (clap derive), TUI (ratatui+crossterm), 19 subcommands, help system, error UX, onboarding transcripts.

  • vim-power-user — modal, dense, keyboard-first
  • accessibility-advocate — NO_COLOR, screen readers
  • onboarding-novice — discoverability, hand-holding
  • cli-unix-purist — pipeable, sysexits, --json
  • visual-designer — layout, color theory, glyphs

DevOps 5 stances

Distribution (curl + Nix), service-manager, releases, code signing, SBOM, mdbook docs, uninstall.

  • nix-purist — flake-as-build, devenv, cachix
  • distro-packager — FHS, XDG, deb/rpm/AUR
  • sre-hawk — structured logs, audit hash chain, runbook
  • supply-chain-sec — minisign, cosign, SLSA L3, SBOM
  • curl-installer-defender — one-line install

Security 5 stances

TUF-lite trust, signatures, 5-mode sandbox gradient, secrets, audit log integrity, IPC auth, supply chain.

  • red-team — default-deny, THREAT_MODEL.md
  • crypto-pedant — ed25519, algorithm-agility envelope
  • sandboxing-veteran — bubblewrap, sandbox-exec, Docker
  • secrets-architect — layered keyring, per-server scope
  • audit-compliance — hash-chained JSONL, SIEM export

UX 5 stances

Onboarding, TUI feel, CLI ergonomics, error envelope, mental model, accessibility, local measurement.

  • empathy-led-designer — tone audit, kind defaults
  • data-driven-pm — local NDJSON event log (no telemetry)
  • onboarding-specialist — 60-second AHA, demo MCP
  • error-recovery-advocate — four-field envelope
  • mental-model-coach — Server / Editor / Secret

Highlights from each facet

The most consequential single decision per facet. Full reasoning lives in each facet's overview.html#decisions; the full list of changes from the v1.0 spec lives in synthesis.html#diffs.

FacetHeadline decisionWhy it matters
Backend Sans-I/O state-machine core (in mcpm-core) + JoinSet/CancellationToken shell + a dedicated OS thread for cgroup-v2 OOM (not a tokio task). The supervisor is the most complex crate. This split makes the pure parts proptest-friendly while keeping the I/O parts idiomatic tokio.
Frontend Three output modes (TTY default → visual; pipe-auto → TSV; --plain → screen-reader prose). Doctor flow folds into mcpm test --diagnostic to preserve the 19-subcommand contract. Pipe-friendliness without sacrificing visual polish; preserved API surface.
DevOps Curl + Nix as dual-primary from the same flake-built artifact, with byte-identical CI gate. Reverse-DNS dev.mcp-manager.mcpmanagerd for macOS launchd / Keychain / libsecret namespaces. Resolves the curl-vs-Nix tension; gives Nix users reproducibility without making curl users second-class.
Security Per-spawn MCPM_INSTANCE_TOKEN nonce on top of SO_PEERCRED, mandatory per-server keychain namespacing, and a SHA-256 hash-chained audit JSONL. Closes the cross-server-as-same-UID secret-read class SO_PEERCRED alone cannot. Audit becomes tamper-evident.
UX Bundle a zero-secret zero-network "time" MCP and install it by default during mcpm init. Four-field error envelope (code/what/why/remedy-as-literal-command). "Toolchains" pane renamed to "Editors". First AHA-moment in <60s without secrets or network; recovery becomes a feature, not an afterthought; the three-noun mental model (Servers/Editors/Secrets) becomes visible.
