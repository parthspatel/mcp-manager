The Tokio Pragmatist's Backend

Idiomatic async Rust. Use the runtime you've got. Lean on tower, tracing, tokio::process, and the rmcp SDK's own conventions. Every line of bespoke supervision, framing, or middleware is a line we will be debugging at 2am — so we don't write it unless the ecosystem genuinely lacks the primitive.

Thoughts

The north star

The v1.0 spec already committed to tokio because rmcp — the official Rust MCP SDK — is built on it[1]. That single decision cascades. We are not designing an async architecture; we are inheriting one that thousands of engineers have battle-tested for years through axum, hyper, reqwest, sqlx, lapin, and the entire serverless-tower-of-babel that powers most production Rust. The honest pragmatist position is: don't fight the ecosystem you live in. Where a maintained crate already solves a sub-problem, use it. Where it doesn't quite fit, layer a thin adapter rather than fork. Where it's truly missing, contribute upstream so the next system benefits too.

Initial reaction to the v1.0 spec

The v1.0 spec gets the runtime call right and then under-specifies the shape of the daemon's request pipeline. "JSON-RPC 2.0 over UDS" tells me the wire format but not how we dispatch handlers, layer cross-cutting concerns (audit, peer-cred check, rate-limit on logs.tail), or evolve method namespaces. The spec also leans on words like "tokio task watches the child" without naming the structured-concurrency pattern (JoinSet? tokio::select!? task per child?). These are exactly the places where naming the abstraction tightens correctness for free.

My three highest-leverage moves:

  1. Adopt tower::Service + a middleware stack for the RPC server. Audit, peer-cred verification, structured tracing spans, rate-limiting, and graceful-shutdown propagation become layers — composable and individually testable. This is exactly the abstraction that powers axum[2] and tonic[3], and it is the cheapest path to a daemon that is auditable by reading the type of Daemon rather than 600 lines of handler imperative.
  2. Use JoinSet<ChildOutcome> for child-process supervision. One JoinSet per managed-process model (singleton + per-client), backed by tokio::process::Command[4]. Restart policy becomes "drive join_next() in a loop; on each completed task, consult the policy, optionally re-spawn." No hand-rolled reaper, no SIGCHLD juggling: tokio::process already drives waitpid for us through its signal-hook-style child-reaper task[5].
  3. Adopt tracing end-to-end with one global subscriber, prod-JSON + dev-tree formatters behind a feature flag. Every span carries the request id, client id (from SO_PEERCRED), server name, and audit-correlation id. The audit log becomes a tracing layer, not a parallel logging system. Free observability for any future tracing-opentelemetry integration[6].

Key concerns about the v1.0 baseline

Three places where idiomatic-async hygiene matters and the spec leaves room to slip:

  • Backpressure on logs.tail. The spec mentions "bounded tokio channel" but doesn't name the policy when the channel is full: drop-oldest, drop-newest, or block? With a TUI subscriber that pauses (alt-screen entry, suspended editor), we will hit this. I want drop-oldest with a counter emitted as a structured event ("tail-client lagging, dropped N lines"). tokio::sync::broadcast[7] gives us this natively — the channel reports RecvError::Lagged(n) to slow consumers without blocking producers.
  • Cancellation discipline. Every long-running task (logs.tail, child-process supervision, periodic trust-refresh) needs a single, named cancellation token. tokio_util::sync::CancellationToken[8] with parent/child relationships is the right primitive. Graceful daemon shutdown is then "cancel the root token; await JoinSet drain with a 5s deadline."
  • Errors at module boundaries. Libraries (mcpm-protocol, mcpm-supervisor) need thiserror-derived enums with #[non_exhaustive]; binaries (mcpm-daemon, mcpm-cli) need anyhow at the seams. Mixing the two — anyhow inside a library — is the most common Rust hygiene smell I see in young projects[9].

Arguments

Against systems-veteran

The veteran wants persistent journals, explicit state machines, and sans-I/O cores — and I broadly respect the discipline. But pushed to v1.0 implementation, the veteran's instinct over-engineers our scale. We are managing 10s of MCPs, not 10,000 containers. A sans-I/O state machine for the supervisor would force us to invent a test harness, a side-channel for time, and a separate driver loop — three things tokio + tokio::time::pause[10] already give us for free in tests.

On persistent journals: yes, the audit log is JSONL and lives on disk. But the veteran's instinct to also journal the supervisor's internal state (which child has been restarted N times, in which window) ignores that JoinSet + an in-memory HashMap<ServerName, RestartHistory> is fine for our scale. If mcpmanagerd dies, we re-derive state from the canonical config + on-disk audit log on startup. We don't need a sled/sqlite-backed state store for a 10-server fleet that fits in 1KB of RAM. Show me the user, at our scale, who benefits from journaling restart-attempt history across daemon restarts — I'll bet you the cost of the sqlite dependency they don't exist.

Where I cede ground: explicit state machines for the supervisor child are correct (Spawning → Running → Crashing → Restarting → Failed). I just want them as enums driven by tokio::select!, not as a sans-I/O reducer. See systems-veteran's design for the alternative.

Against library-author

The library-author wants mcpm-protocol to be a tiny, semver-disciplined, #[non_exhaustive]-everywhere public surface — and on this we mostly agree. Where I push back: the author's instinct to also make mcpm-client publicly versioned, with deprecation cycles and migration guides, is over-engineering for v1.0. mcpm-client is an in-tree convenience layer. The v1.0 spec already says so. Third parties depend on mcpm-protocol; we churn mcpm-client freely. Trying to ship two stable public surfaces is how you get a paralyzed maintainer who refuses to take patches because every change is breaking.

Second disagreement: the library-author tends to want serde's #[serde(deny_unknown_fields)] on every wire type for strictness. I want the opposite — #[serde(default)] + forward-compatible unknown-field tolerance — because we explicitly designed the wire protocol to evolve with new methods and fields (the spec calls out semver-minor additive changes as the common case). Forward-compat tolerance on the client side, strict validation only at the daemon boundary, is the right asymmetry[11].

Where I cede ground: mcpm-protocol deserves the full type-safety regimen — #[non_exhaustive], narrow enums, no String where an enum will do, no Value in public types. See library-author's design.

Against kernel-hacker

The kernel-hacker wants direct libc, hand-managed cgroup file writes, raw signalfd/kqueue on the supervisor, and possibly an io_uring log-write path. This is the place where my pragmatism kicks hardest.

tokio::process::Command is already a thin wrapper over std::process::Command + a shared reaper task; reaching for raw fork/exec + manual waitpid gives us nothing the runtime doesn't already give us, and costs us the entire community's investment in correctness around signal handling, process groups, and orphan reaping[4]. tokio::signal::unix already exposes SIGCHLD / SIGTERM / SIGHUP as async streams — done[5].

cgroupv2 OOM detection: yes, we read memory.events. But via the cgroups-rs crate, not by hand-parsing the file every 100ms[12]. The kernel-hacker's argument is "but cgroups-rs is unmaintained!" — and they're partly right, the crate has stale issues — but the cgroup-v2-fs-rs fork and the simpler approach of "inotify on memory.events + read u64 counters" via tokio::fs covers the v1.0 requirement. Reach for libc if we hit a real ceiling at our scale; we won't.

Where I cede ground: the macOS jetsam heuristic genuinely needs platform-specific work (host_processor_info, proc_pidinfo) — that's a small, well-scoped FFI surface where the kernel-hacker is correct that there's no shortcut. See kernel-hacker's design for the macOS path.

Against boring-tech-defender

The boring-tech-defender wants line-delimited JSON over UDS, hand-rolled request dispatch with a giant match statement, no tower, no streaming-RPC abstractions, and probably log instead of tracing. Their argument: every layer of abstraction is a layer to debug. Fair.

But "boring" cuts two ways. tokio + tower + tracing IS the boring stack for async Rust in 2026. They power axum (the de-facto web framework), tonic (the gRPC client/server), reqwest (the HTTP client), and a large fraction of every production Rust service shipping today[2][13]. Picking them is the conservative move; picking line-delimited JSON + custom dispatch is the contrarian move that loses us middleware composition, instrumentation, and the ability to hire engineers who already know the stack.

Second disagreement: the defender's case against streaming-RPC abstractions ("logs.tail can be implemented as a long-lived JSON-RPC notification stream, that's all") misses that we have multiple streaming endpoints in the spec (logs.tail, and likely server.events in v1.1) and would benefit from a unified abstraction. A tower::Service<Request, Response = BoxStream<Notification>> shape generalizes; "just write a loop" doesn't.

Where I cede ground: not tonic, not grpc. The defender is right that JSON-RPC 2.0 over UDS framed by tokio_util::codec::LengthDelimitedCodec[14] is the right wire format — small, debuggable with socat, no proto files. We're aligned on the wire; we disagree on the dispatcher. See boring-tech-defender's design.

The daemon main loop

Pure tokio + tower. Hyper-style: bind the UDS listener, build a Service stack with layered middleware, accept-loop into per-connection tasks tracked by a JoinSet. 

// crates/mcpm-daemon/src/main.rs
use anyhow::Context;
use tokio_util::sync::CancellationToken;
use tower::ServiceBuilder;
use tracing::instrument;

#[tokio::main(flavor = "multi_thread")]
async fn main() -> anyhow::Result<()> {
    install_tracing()?;                       // tracing-subscriber: JSON in prod, tree in dev
    let cfg = mcpm_core::Config::load()?;     // canonical config
    let shutdown = CancellationToken::new();
    install_signal_handlers(shutdown.clone()); // SIGTERM, SIGINT, SIGHUP → cancel root

    // Component wiring. Each is Send + Sync + Clone (Arc-based internally).
    let registry  = mcpm_registry::Registry::open(&cfg).await?;
    let secrets   = mcpm_secrets::LayeredStore::from_config(&cfg)?;
    let logs      = mcpm_logs::Hub::new(&cfg);
    let trust     = mcpm_trust::TrustStore::open(&cfg, shutdown.child_token()).await?;
    let supervisor = mcpm_supervisor::Supervisor::new(
        secrets.clone(),
        logs.clone(),
        shutdown.child_token(),
    );
    let projector = mcpm_projector::Projector::new(&cfg);
    let core      = mcpm_core::Core::new(cfg, registry, supervisor, projector, logs.clone());

    // tower middleware stack: ordered outer→inner.
    let svc = ServiceBuilder::new()
        .layer(PeerCredAuthLayer::new())            // SO_PEERCRED check
        .layer(TraceLayer::with_correlation_id())   // tracing span per request
        .layer(AuditLayer::new(logs.audit_sink())) // emit JSONL audit event
        .layer(ConcurrencyLimitLayer::new(64))      // bound total in-flight
        .service(RpcHandlers::new(core));           // the actual dispatch

    let listener = bind_uds(&runtime_socket_path())?;
    accept_loop(listener, svc, shutdown.clone()).await
}

#[instrument(skip(listener, svc, shutdown))]
async fn accept_loop<S>(listener: UnixListener, svc: S, shutdown: CancellationToken)
    -> anyhow::Result<()>
where
    S: tower::Service<RpcRequest, Response = RpcResponse> + Clone + Send + 'static,
{
    let mut conns: tokio::task::JoinSet<()> = tokio::task::JoinSet::new();
    loop {
        tokio::select! {
            biased;
            _ = shutdown.cancelled() => break,
            res = listener.accept() => {
                let (sock, _) = res.context("accept")?;
                let svc = svc.clone();
                let tok = shutdown.child_token();
                conns.spawn(async move { drive_connection(sock, svc, tok).await; });
            }
        }
    }
    // graceful drain
    let _ = tokio::time::timeout(std::time::Duration::from_secs(5), conns.join_all()).await;
    Ok(())
}

Every cross-cutting concern is a tower::Layer. Audit is a layer. Tracing is a layer. PeerCred is a layer. The handler is a tower::Service. This composition is exactly the pattern axum and tonic use[2][3], and it gives us a single integration-test pattern: stack the service, call it directly without going through UDS, assert behavior.

mcpm-protocol: small, stable, sans-I/O

The library-author was right that this crate is special. It carries every wire type. I keep it sans-I/O, serde-derived, #[non_exhaustive] on every public enum, and thiserror for the single error type.

#[serde(default)] on optional params means a v1.1 client speaking to a v1.0 daemon (or vice versa) tolerates unknown fields. The wire-version handshake is a single daemon.status round-trip on connect.

mcpm-supervisor: JoinSet + state-machine enum + cancellation tokens

One JoinSet<ChildOutcome> per supervisor instance. Restart policy is a small function that takes (history, now) and returns Either<Sleep(Duration), Fail>. Process index is a HashMap keyed by ProcessKey, which is either Server(name) (singleton) or (Server(name), ClientId) (per-client). The cgroupv2 OOM-watch + RLIMIT_AS fallback live behind a single platform trait. 

// crates/mcpm-supervisor/src/lib.rs
use std::collections::HashMap;
use std::time::Duration;
use tokio::process::{Child, Command};
use tokio::task::JoinSet;
use tokio_util::sync::CancellationToken;

#[derive(Debug, Clone, Hash, Eq, PartialEq)]
pub enum ProcessKey {
    Singleton(String),                       // server name
    PerClient { server: String, client: ClientId },
}

#[derive(Debug)]
pub enum ChildOutcome {
    Exited { key: ProcessKey, status: std::process::ExitStatus },
    OomKilled { key: ProcessKey, evidence: OomEvidence },
    Cancelled { key: ProcessKey },
}

pub struct Supervisor {
    procs: parking_lot::Mutex<HashMap<ProcessKey, ProcState>>,
    secrets: mcpm_secrets::LayeredStore,
    logs: mcpm_logs::Hub,
    children: tokio::sync::Mutex<JoinSet<ChildOutcome>>,
    root_cancel: CancellationToken,
}

struct ProcState {
    spec: ServerSpec,
    refcount: u32,
    history: RestartHistory,
    state: ProcLifecycle,           // Spawning | Running | Crashing | Restarting | Failed
    idle_timer: Option<tokio::task::JoinHandle<()>>,
    cancel: CancellationToken,      // child of root_cancel
}

impl Supervisor {
    pub async fn ensure_running(&self, key: ProcessKey) -> Result<StdioPipe, SupError> {
        let mut procs = self.procs.lock();
        if let Some(state) = procs.get_mut(&key) {
            state.refcount += 1;
            if let Some(t) = state.idle_timer.take() { t.abort(); }
            return Ok(state.stdio_pipe());
        }
        drop(procs);
        self.spawn(key).await
    }

    async fn spawn(&self, key: ProcessKey) -> Result<StdioPipe, SupError> {
        let spec = self.lookup_spec(&key)?;
        let env = self.secrets.resolve_env(&spec).await?;            // SecretString → OsString at syscall
        let cancel = self.root_cancel.child_token();

        let mut cmd = Command::new(&spec.command);
        cmd.args(&spec.args).envs(env).stdin(std::process::Stdio::piped())
           .stdout(std::process::Stdio::piped()).stderr(std::process::Stdio::piped())
           .kill_on_drop(true);
        let child = cmd.spawn()?;

        // Platform-specific memory limit setup (cgroup v2 / RLIMIT_AS / nothing on macOS).
        platform::apply_memory_limit(&child, spec.memory_max_mb)?;
        let oom_watch = platform::oom_watch(child.id().unwrap(), spec.memory_max_mb, cancel.clone());

        let pipe = StdioPipe::new(&child, &self.logs, &spec.name);
        let key2 = key.clone();
        self.children.lock().await.spawn(async move {
            tokio::select! {
                biased;
                _ = cancel.cancelled() => ChildOutcome::Cancelled { key: key2 },
                ev  = oom_watch => ChildOutcome::OomKilled { key: key2, evidence: ev },
                res = child.wait() => ChildOutcome::Exited { key: key2, status: res.unwrap() },
            }
        });
        // record state, return pipe
        Ok(pipe)
    }

    /// Drives the JoinSet forever; runs as one background task on daemon start.
    pub async fn drive(&self) {
        loop {
            let mut children = self.children.lock().await;
            tokio::select! {
                biased;
                _ = self.root_cancel.cancelled() => { children.shutdown().await; return; }
                Some(outcome) = children.join_next() => {
                    drop(children);
                    self.handle_outcome(outcome.unwrap_or_else(panic_outcome)).await;
                }
            }
        }
    }

    async fn handle_outcome(&self, outcome: ChildOutcome) {
        match outcome {
            ChildOutcome::Exited { key, status } => self.maybe_restart(key, ExitKind::Crash(status)).await,
            ChildOutcome::OomKilled { key, evidence } => self.maybe_restart(key, ExitKind::Oom(evidence)).await,
            ChildOutcome::Cancelled { .. } => { /* expected on shutdown */ }
        }
    }

    async fn maybe_restart(&self, key: ProcessKey, kind: ExitKind) {
        let decision = {
            let mut p = self.procs.lock();
            let st = match p.get_mut(&key) { Some(s) => s, None => return };
            st.history.record(kind, Instant::now());
            restart_policy(&st.spec.restart, &st.history)
        };
        match decision {
            Decision::Sleep(d) => {
                tokio::time::sleep(d).await;
                let _ = self.spawn(key).await;          // re-spawn
            }
            Decision::Fail => {
                self.mark_failed(&key, kind).await;     // emit audit + tracing event
            }
        }
    }
}

fn restart_policy(p: &RestartPolicy, h: &RestartHistory) -> Decision {
    let attempts = h.in_last(p.window_secs);
    if attempts >= p.attempts_max { return Decision::Fail; }
    // exponential + jitter
    let base = Duration::from_millis(200);
    let exp  = base.checked_mul(1 << attempts.min(8)).unwrap_or(Duration::from_secs(60));
    let jitter = rand::random::<f64>() * 0.3;
    Decision::Sleep(exp.mul_f64(1.0 + jitter).min(Duration::from_secs(60)))
}

The structure makes failure modes testable in isolation. tokio::time::pause()[10] lets a unit test fast-forward through the backoff schedule without sleeping for real. JoinSet handles fan-out; CancellationToken handles fan-in for shutdown.

OOM detection — platform trait

PlatformSignalImplementation
Linux cgroupv2deterministiccgroups-rs attach + inotify on memory.events; parse oom_kill counter delta
Linux cgroupv1best-effortsetrlimit(RLIMIT_AS, …) at pre_exec; on SIGKILL exit, emit "may have been OOM" audit note
macOSheuristicSIGKILL exit + host_processor_info() memory-pressure within 30s + RSS > 80% of limit (sampled every 5s into a small ring) — all three required
 
#[cfg(target_os = "linux")]
mod platform {
    pub async fn oom_watch(pid: u32, limit_mb: u32, cancel: CancellationToken)
        -> OomEvidence
    {
        let events_path = format!("/sys/fs/cgroup/mcpm/{}/memory.events", pid);
        let mut watcher = inotify::Inotify::init().unwrap();
        watcher.add_watch(&events_path, inotify::WatchMask::MODIFY).unwrap();
        let mut stream = watcher.event_stream(Vec::with_capacity(4096)).unwrap();
        let mut last_oom = read_oom_count(&events_path).await.unwrap_or(0);
        loop {
            tokio::select! {
                _ = cancel.cancelled() => return OomEvidence::Cancelled,
                Some(_) = stream.next() => {
                    let cur = read_oom_count(&events_path).await.unwrap_or(last_oom);
                    if cur > last_oom { return OomEvidence::Cgroupv2(cur - last_oom); }
                    last_oom = cur;
                }
            }
        }
    }
}

#[cfg(target_os = "macos")]
mod platform {
    pub async fn oom_watch(pid: u32, limit_mb: u32, cancel: CancellationToken)
        -> OomEvidence
    {
        // sample RSS every 5s into a ring; on cancel, return what we've got.
        let mut ring = RssRing::with_capacity(32);
        let mut ticker = tokio::time::interval(Duration::from_secs(5));
        loop {
            tokio::select! {
                _ = cancel.cancelled() => return OomEvidence::macOsRing(ring),
                _ = ticker.tick() => {
                    if let Some(rss) = libproc_rss_mb(pid) { ring.push(rss, Instant::now()); }
                }
            }
        }
    }
}

mcpm-logs: three streams, one broadcast channel each

The spec's "3-stream tail API" maps cleanly to one tokio::sync::broadcast::Sender per stream class[7]. Broadcast natively reports Lagged(n) to slow receivers without blocking producers — exactly the backpressure semantics I want for logs.tail. 

// crates/mcpm-logs/src/lib.rs
pub struct Hub {
    daemon: tokio::sync::broadcast::Sender<LogLine>,
    servers: dashmap::DashMap<String, tokio::sync::broadcast::Sender<LogLine>>,
    audit_writer: tokio::sync::mpsc::Sender<AuditEvent>,
    audit_task: tokio::task::JoinHandle<()>,
}

impl Hub {
    pub fn subscribe_daemon(&self) -> impl Stream<Item = LogLine> {
        let rx = self.daemon.subscribe();
        broadcast_stream(rx).filter_map(|r| async move {
            match r {
                Ok(line) => Some(line),
                Err(BroadcastStreamRecvError::Lagged(n)) => Some(LogLine::lagged(n)),
            }
        })
    }
    // similar for per-server, audit
}

Audit JSONL is single-writer (one mpsc receiver flushing every 100ms or 4KB into a daily-rotated file via tracing-appender::rolling::daily[15]).

mcpm-secrets: trait + spawn_blocking

The keyring crate is sync (it goes through libsecret/Keychain blocking APIs). Wrapping in spawn_blocking on the trait surface keeps the async story uniform and gives us a single place to apply a timeout if the keychain prompts for user attention. 

#[async_trait::async_trait]
pub trait SecretStore: Send + Sync + 'static {
    async fn get(&self, name: &str) -> Result<Option<secrecy::SecretString>, SecretError>;
    async fn set(&self, name: &str, value: secrecy::SecretString) -> Result<(), SecretError>;
    async fn unset(&self, name: &str) -> Result<bool, SecretError>;
    async fn list(&self) -> Result<Vec<String>, SecretError>;
}

pub struct OsKeyringStore { service: String }

                Err(e) => Err(SecretError::Backend(e.to_string())),

    }

}

mcpm-projector: tokio::fs + atomic temp-rename

Per-editor adapters are stateless. Managed-block sync = read existing config, replace the fenced region (delimited by # BEGIN MANAGED BY MCPM and # END MANAGED BY MCPM), write to a temp file in the same directory, fsync, atomic rename. All async via tokio::fs. 

async fn write_managed_block(
    path: &Path,
    block: &str,
    fence: &ManagedFence,
) -> Result<(), ProjectError> {
    let existing = match tokio::fs::read_to_string(path).await {
        Ok(s) => s,
        Err(e) if e.kind() == std::io::ErrorKind::NotFound => String::new(),
        Err(e) => return Err(e.into()),
    };
    let new = splice_fenced_region(&existing, block, fence);

    let tmp = path.with_extension("mcpm-tmp");
    {
        let mut f = tokio::fs::File::create(&tmp).await?;
        tokio::io::AsyncWriteExt::write_all(&mut f, new.as_bytes()).await?;
        f.sync_all().await?;
    }
    tokio::fs::rename(&tmp, path).await?;
    Ok(())
}

JetBrains XML is the one outlier: we use quick-xml in serialize-from-typed mode, never raw string concatenation, to avoid XML-injection on server names with brackets in them.

mcpm-client: dial-or-spawn, then wrap in a tower service

pub async fn connect() -> Result<Client, ConnectError> {
    let sock = runtime_socket_path()?;
    for attempt in 0..5 {
        match tokio::net::UnixStream::connect(&sock).await {
            Ok(s) => return Ok(Client::wrap(s)),
            Err(e) if attempt == 0 && should_autospawn(&e) => {
                spawn_daemon_under_flock(&sock).await?;
            }
            Err(_) => tokio::time::sleep(Duration::from_millis(50)).await,
        }
    }
    Err(ConnectError::Timeout)
}

Cross-cutting: tracing + audit

One tracing_subscriber::Registry on daemon start, multiple layers fan in: fmt::Layer (human or JSON), AuditLayer (filtered by target=audit), EnvFilter for verbosity, tracing_appender for daily-rotated daemon log[15]. Every handler is #[instrument(skip(...))]. The audit JSONL is then just events with target = "mcpm::audit" — already filterable, already structured, already correlatable with daemon-log spans via the trace-id field.

What I explicitly will NOT do

  • No bespoke async runtime. No glommio, no smol, no monoio. rmcp chose tokio; we choose tokio.
  • No actix. Not idiomatic in this stack. Tower is idiomatic.
  • No tonic / gRPC / protobuf. JSON-RPC 2.0 stays. tokio_util::codec::LengthDelimitedCodec for framing.
  • No SQLite, no sled, no rocksdb in v1.0. Audit is JSONL on disk; supervisor state is in-memory + re-derived from config on startup. systems-veteran disagrees; this is one we'll relitigate at v2.
  • No custom OOM kernel module. kernel-hacker proposes one; for our scale it's overkill.
  • No raw fork/exec. tokio::process::Command all the way.

Cross-references to other facets

The wire-format discussion belongs in the security facet (peer-cred + framing) and the UX facet (latency budget). The projector's editor adapters are heavily UX-dependent — see the frontend facet for the TUI-side error rendering when a managed-block write conflicts with a hand-edited section. DevOps owns the daily rotation + JSONL retention policies (devops facet).

Summary in one sentence

Use the runtime rmcp chose, layer tower middleware over a sans-I/O mcpm-protocol, structure the supervisor as a JoinSet driven by a CancellationToken tree, and let tracing + broadcast + thiserror earn their keep across every crate.
