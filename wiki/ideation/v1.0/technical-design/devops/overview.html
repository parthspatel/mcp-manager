DevOps — Facet Synthesis

Where the five devops stances converge, where they diverge, and what we actually adopt for v1.0. The locked inputs — curl installer + Nix flake (no Homebrew, no App Store), macOS+Linux only, auto-spawn daemon, service-manager auto-register/unregister, no telemetry, Apache 2.0, Renovate vocabulary, Cargo/npm-style ranges+lockfile, minisign for index, cosign-when-present for packages, mdbook docs — sit on the table. The five agents argue about how to honour those inputs, not whether to. This synthesis closes those arguments.

Where the five agree

Strip the rhetoric and the five essays land on a surprising number of shared positions. Listing them once is the cheapest way to free up budget for the genuinely contested decisions.

One: curl + Nix is correct — in that order of visibility

The nix-purist concedes the curl installer is the path 95% of users take and explicitly designs around it. The curl defender agrees Nix is the second channel ("v1.0 ships both, this is not either-or"). The distro packager accepts distros are downstream for v1.0; the SRE and supply-chain both accept Nix-as-build-system but reject Nix-as-runtime-dependency. There is no real fight here, only an argument about which channel is "canonical" — settled in decisions.

Two: minisign is the primary release signature

All five converge on minisign for the release-tarball envelope. The supply-chain essay makes the strongest case ("ed25519, no PKI, no X.509 disasters"); the curl defender writes the two-step verify into the installer; the nix-purist wants minisign on the tarball and a cachix substituter key for the Nix path; the distro packager uses minisign as the upstream signature that downstream deb/rpm signing layers on top of. No agent argues for GPG. Cosign-when-present for OCI packages is unanimous: additive verification, never sole.

Three: macOS+Linux only, no Windows, no Homebrew, no App Store

Five for five. The lockdown is honoured by all five essays without re-litigation. Cross-platform handling lives in the binary itself (launchd vs. systemd-user, sandbox-exec vs. bubblewrap, Keychain vs. libsecret); the same flake / same tarball / same artifact lands on both platforms. The distro packager spends a paragraph on Apple's /usr/local SIP situation but lands on the same place (default /usr/local/bin with a --prefix escape hatch).

Four: structured-JSON logs + journald/launchd integration

The SRE drives this position, but every other agent agrees in passing. The distro packager explicitly trades structured-JSON-on-stdout for free journald + unified-log integration ("we are emitting the logs anyway"). The supply-chain agent accepts JSONL-with-stable-schema as the only way an audit log can be ingested for off-line analysis. The curl defender hangs their observability story on the OS's native logging stack instead of inventing a parallel pipeline.

Five: no telemetry — full stop

The locked policy is explicit, and no agent attempts to revisit it. The SRE names what no-telemetry costs us — field-error blindness, CVE-impact opacity — and designs around it via mcpm doctor --share as an opt-in per-incident bundle. The supply-chain agent welcomes no-telemetry as a security positive ("no network egress path becomes itself a supply-chain concern").

Six: manifest-driven uninstall, logs + secrets preserved by default

Four of the five specify the same shape: an on-disk install manifest enumerates every file the installer touched; mcpm uninstall walks the manifest; logs + audit + keychain entries are preserved by default and removed only on --purge with explicit confirmation. The distro packager wrote the most rigorous enumeration table; the supply-chain agent extends it to a keychain-namespace prune; the SRE writes the human-facing prompt; the curl defender puts the uninstaller inside the mcpm binary itself — one fewer signed artifact to maintain.

Seven: reproducible builds are non-negotiable

The nix-purist demands a build-twice gate enforced by Nix path equality; the supply-chain agent demands SOURCE_DATE_EPOCH + --remap-path-prefix + codegen-units = 1 with a build-twice diff in CI; the distro packager and curl defender both accept the claim as load-bearing. The flake becomes the reference reproducible build; the tarball is verified against the flake's output hash in CI. Non-reproducibility is itself an alarm signal.

Eight: dev.mcp-manager.mcpmanagerd reverse-DNS namespace

All five accept the locked choice. The distro packager writes the rationale (launchd's Label is a global namespace; reverse-DNS is the Apple-standard mitigation). The same string lands as macOS Keychain service prefix, Linux libsecret schema, macOS os_log subsystem, and launchd label. The systemd-user unit deliberately uses bare mcp-manager.service — systemd convention, honoured by every agent.

Nine: mdbook in-repo, GitHub Pages-served, no CDN

Unanimous. The nix-purist builds mdbook in the flake so docs build reproducibly; the distro packager wires the docs URL into manpages' SEE ALSO sections; the supply-chain agent adds a /security/ advisories subsection; the SRE demands a Runbook chapter; the curl defender notes mdbook's static-output matches our no-CDN constraint.

Where they disagree

One: which install channel is "primary"

The nix-purist insists "primary should mean the source of truth for what gets built" — the flake produces the canonical artifact, the curl installer downloads tarballs the flake produced. The curl defender reads "primary" as user-facing and rejects any architecture that makes the curl path feel like an afterthought. The distro packager rejects both framings: distro packages are how 95% of Linux users actually install software, and curl/Nix are both transitional. The SRE doesn't care about "primary" but insists the binary must run on a stock OS with no Nix, no Homebrew, nothing — otherwise the doctor that fixes broken systems can itself be broken by them.

Resolution: the lockdown's "curl installer + Nix flake" is a dual primary. Both are first-class; both ship from the same artifact; the curl installer is the default invocation in our docs and the flake is the default invocation for Nix users. This is captured in decisions.

Two: how aggressive to be about supply-chain ceremony

The supply-chain agent wants two ed25519 root keys on YubiKey FIPS tokens (release + trust-manifest), SLSA L3 provenance per release, CycloneDX SBOM signed with the release key, cargo-vet imports from five orgs, cargo-deny with a strict license allow-list. The curl defender agrees but rejects requiring the user to install cosign or GPG — minisign verification has to be performed by a sidecar binary the installer fetches. The nix-purist wants the cachix substituter key as a parallel trust root for Nix users. The SRE adds the audit log itself must be hash-chained — pre-incident signing is not the same property as post-incident verifiability.

Resolution: take the union on the release side — minisign primary, cosign-when-present, CycloneDX 1.5 JSON SBOM, SLSA L3, reproducible-build CI gate. Add the SRE's hash-chained audit log to the runtime side. Users are not required to install cosign or GPG. Two-key separation is deferred to v1.1 (single maintainer, single token in v1.0).

Three: how Linux paths are laid out

The distro packager wants FHS rigour — mcpmanagerd in libexec (invoked indirectly), 17 manpages auto-generated by clap_mangen. The curl defender defaults to $HOME/.local on Linux for the curl path (no sudo) and /usr/local/bin on macOS. The SRE objects to /var/log/mcpmanagerd/ — user daemons go under $XDG_STATE_HOME.

Resolution: curl path defaults $PREFIX = /usr/local on macOS, $HOME/.local on Linux (with auto-fallback if /usr/local/bin is not writable). State and logs go under $XDG_STATE_HOME. The libexec location applies only to deb/rpm recipes; the curl-installed daemon lives in $PREFIX/bin/mcpmanagerd alongside mcpm so auto-spawn's which mcpmanagerd just works. Manpages: ship in v1.0, auto-generated where possible; the 17-manpage roster is aspirational, the floor is ~12 (top-level + one per major subcommand).

Four: do we ship deb/rpm/AUR ourselves in v1.0?

The distro packager wants cargo deb / cargo generate-rpm / pkg/PKGBUILD recipes in-tree, with the .deb/.rpm/.tar.gz shipped as release artifacts (but no apt repo / no dnf repo / AUR-only for Arch). The curl defender objects to the maintenance load and points out the cadence mismatch (we ship patch releases every 1–2 weeks, distros don't). The nix-purist dismisses deb/rpm as an 8× build matrix we don't need. The supply-chain agent appreciates that distro packages bring their own attestation infrastructure but agrees the inclusion review process (6–18 months) doesn't fit v1.0.

Resolution: recipes in-tree, packages shipped as release artifacts, no apt/dnf repos owned by us. Arch AUR is the one exception — AUR has no gate, the Arch community expects the upstream to keep the PKGBUILD warm, and the maintenance burden is low. Debian/Fedora packaging is left to downstream volunteers in v1.0; we provide the recipes so the friction is minimal. This matches the locked-decisions table: "no Homebrew, no App Store" doesn't exclude AUR or community-driven downstream packages; it excludes channels we'd own.

Five: how the daemon binary path is resolved at auto-spawn

The SRE wants a sharper picture of the spawn race: flock(2), ENOENT-vs-ECONNREFUSED handling, stale-socket recovery, and a counter in mcpm doctor. The supply-chain agent rules out spawn-time signature verification on the binary (50ms budget). The nix-purist wants the lookup to be which mcpmanagerd via $PATH — no special-casing for Nix vs. curl. The curl defender agrees on $PATH resolution but adds an install-manifest receipt that doctor can cross-check.

Resolution: $PATH-based lookup (the v1.0 spec's design), plus the SRE's stale-socket-recovery counter and the install-manifest receipt that the doctor verifies on demand. No spawn-time signature verification — the 50ms p99 budget rules.

Per-component decisions

1. Distribution — curl + Nix relationship

Two co-equal install channels, one artifact, one build. The release pipeline builds via the flake (nix flake check on four target systems), produces the tarballs as derivation outputs, and uploads them to GitHub Releases. The Nix path consumes the flake outputs directly; the curl path downloads the tarballs from the release. The byte-identical-artifact property is enforced by CI: a separate job rebuilds nix build .#mcp-manager and asserts SHA256 equality with the release artifact.

Default-install messaging: our docs lead with curl -fsSL https://mcp-manager.dev/install.sh | sh as the default install command; the Nix flake usage (nix profile install github:user/mcp-manager or inputs.mcp-manager.url in flake.nix) is documented as a peer, not a footnote. The installer script can optionally detect nix on $PATH and offer to shell out to nix profile install (this is the nix-purist's compromise) — deferred to v1.1; v1.0 the curl installer drops a static binary regardless of Nix presence.

2. Build / release pipeline — reproducibility

Reproducible-build flags non-negotiable: SOURCE_DATE_EPOCH, --remap-path-prefix, codegen-units = 1, lto = "fat", panic = "abort", strip = "symbols", --locked, --offline, build-twice diff step. The supply-chain essay's recipe is the canonical one. The flake encodes the same pinning via rust-overlay + Crane.

CI matrix: four runners (x86_64-linux, aarch64-linux, x86_64-darwin, aarch64-darwin). Single command per runner: nix flake check -L. A fifth job runs the reproducibility-gate rebuild. SLSA L3 provenance via slsa-framework/slsa-github-generator. macOS binaries notarized via Apple Developer Program. Linux tarballs minisign-signed.

3. Code signing

Linux tarballs: minisign on the tarballs and on SHA256SUMS. The minisign pubkey is baked into the installer script and into the released binary and published at https://mcp-manager.dev/release-key.pub + in the README + in the GitHub repo description (multiple-witness corroboration, supply-chain's design).

macOS: hardened-runtime, signed with Apple Developer ID Application, notarized via notarytool, stapled. Gatekeeper passes on first run.

Touch ID / biometric: deferred to v1.1 per the locked decisions ("best-effort in v1.0"). When implemented, the keychain ACL on each secret will set kSecAttrAccessibleWhenUnlockedThisDeviceOnly + kSecAttrAccessControl with biometryAny. Not blocking for v1.0.

Cosign-when-present is the registry-package verification path, behind a feature flag in mcpm-registry. The release signing itself stays minisign-only in v1.0; sigstore-keyless is an additive verification path users can adopt downstream but not a required dependency on Fulcio/Rekor for our publication pipeline.

4. Service manager — systemd-user + launchd

Linux: systemd-user unit at ~/.config/systemd/user/mcp-manager.service (curl install) or /usr/lib/systemd/user/mcp-manager.service (deb/rpm). Socket-activated (mcp-manager.socket at $XDG_RUNTIME_DIR/mcp-manager/mcpmanagerd.sock). Type=notify; daemon calls sd_notify(READY=1) after binding the UDS. StandardOutput=journal + StandardError=journal; the daemon emits JSON-per-line so journalctl --user-unit mcp-manager --output=json Just Works. Resource limits and the security hardening directives are taken verbatim from distro-packager's unit — NoNewPrivileges, ProtectSystem, RestrictAddressFamilies=AF_UNIX, etc.

macOS: LaunchAgent (user-mode, never daemon-mode) at ~/Library/LaunchAgents/dev.mcp-manager.mcpmanagerd.plist. RunAtLoad=false, KeepAlive=false — we use launchd's socket activation via the Sockets dictionary, so the daemon spawns on first connect and exits cleanly on idle-timer expiry. UDS path is ~/Library/Application Support/mcp-manager/mcpmanagerd.sock (macOS lacks $XDG_RUNTIME_DIR). ProcessType=Background; NumberOfFiles=1024.

Naming: systemd unit is mcp-manager.service (no reverse-DNS — systemd convention is package-name-shaped). launchd label is dev.mcp-manager.mcpmanagerd (reverse-DNS — Apple convention). Keychain/libsecret namespace is dev.mcp-manager.mcpmanagerd on both.

5. Auto-spawn daemon

The locked design says mcpm-client's connect() auto-spawns on ENOENT/ECONNREFUSED. We adopt the SRE's sharper specification: flock(2) on a sibling lockfile; 5-second timeout for the winning daemon to become ready; stale-socket recovery treats ECONNREFUSED the same as ENOENT but logs a higher-severity audit event so we can track frequency. Daemon path lookup is plain which mcpmanagerd via $PATH — no Nix vs. curl branching.

Service-manager-mediated auto-start: when the user runs mcpm init, the CLI offers to register the launchd plist / systemd-user socket unit. Default: register (locked: "Service manager auto-register on init"). Idempotent: re-running mcpm init with the unit already present is a no-op. The companion mcpm uninstall unregisters (locked: "auto-unregister on uninstall"). An audit event service.register / service.unregister fires either way.

6. Update mechanism — Renovate vocabulary + pinning

v1.0 ships no self-updater. Users update by:

  • Curl path: re-running the installer (idempotent; install manifest detects in-place upgrade; the old daemon keeps running until mcpm daemon restart). The installer atomically replaces the binary via rename(2), then prints "restart with systemctl --user restart mcp-manager.socket (or launchctl kickstart -k gui/$UID/dev.mcp-manager.mcpmanagerd) when convenient."
  • Nix path: nix profile upgrade mcp-manager — atomic profile swap with nix profile rollback available.
  • Downstream packaged path: distro's native upgrade command.

Renovate vocabulary applies to MCP server pinning, not to the supervisor itself (which only has semver). PATCH, MINOR, MAJOR, DIGEST, PIN, MAINT, and the SPEC bump (MCP protocol version) classify updates returned by mcpm outdated. The nix-purist's observation maps cleanly: Cargo/npm-style range-in-manifest + exact-in-lockfile is the same shape as flake-input + flake.lock; both encode "what range is acceptable" separately from "what we resolved last time."

7. Cross-platform — macOS + Linux only

Four release tarballs: x86_64-apple-darwin, aarch64-apple-darwin, x86_64-unknown-linux-gnu, aarch64-unknown-linux-gnu. Glibc-linked, not musl. Static where possible (Rust std, system libraries via rpath when needed). No Windows. No musl variant in v1.0.

Platform-specific code paths inside the daemon (OS sandboxing, OOM detection per the spec's per-platform table, service manager, keychain) are detected at runtime, not via separate builds. One flake, one binary per target.

8. SBOM + supply chain

SBOM format: CycloneDX 1.5 JSON, generated by cargo-cyclonedx in CI on every tag. Attached to every GitHub release as mcp-manager-1.0.0-<target>.cdx.json + minisign signature. The nix-purist's parallel proposal — sbomnix walks the flake derivation graph — runs as a secondary check; we attach both SBOMs when they agree, and a discrepancy blocks the release.

cargo-deny (license + advisory + ban gate) runs on every PR + daily cron. cargo-vet imports audits from Mozilla, Google, Bytecode Alliance, Embark, Zcash; we own audits only for the unaudited delta (~50 crates). cargo-audit daily on main; auto-issue on new RUSTSEC advisory; security patch within 7 days for High/Critical. The supply-chain agent's deny.toml is the canonical config.

SLSA Build Level 3 at v1.0 GA via slsa-framework/slsa-github-generator. L4 (parameterless, hermetic) aspirational.

Hash-chained audit log (the SRE's ask): every audit JSONL line carries seq (monotonic per-day) and prev_hash (sha256 of the previous canonical-JSON line). Day-boundary cross-references close one day's chain into the next. mcpm audit verify verifies the chain; mcpm doctor runs it as part of its checks.

9. mdbook docs hosting

Source at docs/ in the repo. Built by mdbook build in CI — produced as a flake derivation (packages.docs) so the build is reproducible. Published to https://mcp-manager.dev/docs/ via GitHub Pages. Versioned per release at /docs/v1.0/; /docs/latest/ redirects to current.

Required chapters for v1.0: install (curl + Nix), tutorial, CLI reference, config reference, runbook (SRE's chapter shape: daily ops / common failures / incident response / recovery procedures / reference), security (SECURITY.md + advisories + pubkeys + SBOM links + reporting), and the developer-facing protocol spec (mcpm-protocol crate's wire types).

10. Service-string namespace — dev.mcp-manager reverse-DNS

macOS launchd label, macOS Keychain service prefix, Linux libsecret schema, macOS os_log subsystem: dev.mcp-manager.mcpmanagerd. Reverse-DNS, lowercase. The project owns mcp-manager.dev; dev.-prefixed reverse-DNS signals project-not-corporation.

systemd unit name: mcp-manager.service + mcp-manager.socket. systemd convention is package-name; reverse-DNS in unit names breaks tab-completion.

Why the asymmetry is correct: each namespace is a different OS's global identifier space, and each OS has its own collision-avoidance convention. We follow each platform's convention rather than enforce a single string everywhere. The distro-packager's table is the canonical mapping.

11. mcpm uninstall correctness

The contract: on completion, no file written by mcpm/mcpmanagerd remains on disk, no service-manager registration remains, no $PATH entry we wrote remains, no projected managed-blocks remain in editor configs. Preserved by default: audit log + per-server logs (the SRE's argument — uninstall often follows a failed support thread) and keychain entries (the supply-chain agent's argument — secrets cannot be recovered, removal requires explicit consent). --purge removes everything, with separate interactive confirms for keychain entries.

Source of truth: $XDG_STATE_HOME/mcp-manager/install.manifest (the distro-packager's format: event abs-path sha256 ISO-8601-timestamp, append-only). For deb/rpm-installed copies, the package format is the manifest — mcpm uninstall detects this case and refuses with "use apt remove / dnf remove instead." Critical guard against double-uninstall of package-managed copies.

Last act: write a final audit line {"event":"uninstall","outcome":"ok","purge":false,"audit_kept":true,"logs_kept":true}, fsync, then drop the binary. The audit file ends with a clear marker. Forensic trail preserved up to the moment of teardown.

Projection teardown: for each editor in projection.lock, strip the managed-block fenced region from the editor's config (between # BEGIN mcp-manager and # END mcp-manager markers). Never touch unmanaged content. The supply-chain agent's "leave no trust state behind" framing extends this to keychain-namespace prune — enumerate every entry under the dev.mcp-manager.mcpmanagerd service prefix and delete each (on --purge only, with confirmation).

Open questions

Items the five agents did not fully resolve. None are blockers for v1.0 implementation; each is captured here so the engineering pass can pick a default.

A — sidecar verify-helper bootstrap

The curl defender ships a static mcpm-verify sidecar binary that the installer downloads, verifies against an embedded hash, and uses to run the minisign + sha256 check. The supply-chain agent's installer prefers the user to have minisign already installed (via brew/apt/dnf). Trade-off: sidecar means one fewer dependency on the user's environment, but adds one more signed artifact we maintain. Default: follow the curl defender — ship the sidecar; the supply-chain agent's pre-installed-minisign path is the fallback if the sidecar download fails.

B — flake-built docs as part of the release

The nix-purist wants nix build .#docs in CI to publish to GitHub Pages, so the published HTML is bit-identical from any contributor's machine. The curl defender proposes plain mdbook build. Both work; the flake-built path costs nothing extra given the flake is already in the build pipeline. Default: flake-built; the docs derivation is part of the same nix flake check CI run.

C — two-key signing (release vs. trust manifest)

The supply-chain agent argues for two ed25519 root keys on separate YubiKey FIPS tokens: KR for releases, KT for trust-manifest. Separation of duties; one compromised key doesn't compromise the other. v1.0 ships with a single maintainer; the two-key ceremony is theatre at our current scale. Default for v1.0: single key, single token, documented rotation procedure. Two-key separation is a v1.1 add-on when we have multiple maintainers.

D — musl-static Linux build for Alpine

Locked v1.0 covers x86_64-unknown-linux-gnu + aarch64-unknown-linux-gnu only. The curl defender's VM matrix runs Alpine with "expected: works with limitations" status. Real Alpine support requires musl-target builds (libsecret has musl issues; we'd need to vendor or use a different secret store). Default for v1.0: Alpine is best-effort; musl variants are a v1.1 add-on.

E — zero-downtime daemon hand-off

The SRE sketches a v1.1 design via SCM_RIGHTS-passing of child stdio FDs between old and new daemon processes during update. Out of scope for v1.0; calling out so the daemon's process model doesn't accidentally close the door on it. v1.0's update flow is graceful-stop + restart + re-spawn-autostart-servers, with editors briefly losing their MCP-server connections.

F — mcpm doctor scope

The SRE writes an extensive doctor sketch (14 checks, hash-chain verify, projection drift, install-receipt integrity). v1.0 floor: 8 checks (binary integrity, daemon liveness, config validity, audit chain, log rotation, per-server health summary, secret store reachability, registry trust status). Doctor's full surface (14+ checks, --share bundle) is iterative; the 8 floor checks are part of v1.0 GA. The diagnostic-as-telemetry-substitute role argues for early investment.
